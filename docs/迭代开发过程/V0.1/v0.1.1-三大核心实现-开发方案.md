## 三、方案设计

### 3.1 createMockFactory 默认值生成规则（Oracle 修订版）

> **核心决策（Oracle 审核）**：TS 类型运行时完全擦除，「运行时无类型信息 + 不新增 as any + 递归生成合法值」三者无法同时满足。
> **结论**：引入**轻量运行时 schema**（`_types` 描述符），输入是运行时数据，输出是 `Record<string, unknown>`，不使用泛型断言生成值。

#### 3.1.1 运行时 schema 类型定义

```typescript
// MockFieldSchema — 运行时字段类型描述符
interface MockFieldSchema {
  kind: "string" | "number" | "boolean" | "date" | "enum" | "object" | "array";
  /** kind="enum" 时的候选值（运行时值列表） */
  enumValues?: readonly (string | number)[];
  /** kind="array" 时的元素 schema */
  element?: MockFieldSchema;
  /** kind="object" 时的嵌套字段描述 */
  fields?: Record<string, MockFieldSchema>;
  /** 是否为 id 类字段（自增） */
  isId?: boolean;
}

// MockFactoryOptions — createMockFactory 的配置
interface MockFactoryOptions<T> {
  /** 运行时字段类型描述（轻量 schema，镜像 T 的结构） */
  _types?: Record<keyof T, MockFieldSchema> | MockFieldSchema;
  /** 枚举值列表（运行时值）：{ status: ["DRAFT", "PUBLISHED"] } */
  _enums?: Record<string, readonly (string | number)[]>;
  /** 确定性种子（默认 42） */
  _seed?: number;
  /** 最大递归深度（默认 3，防循环引用） */
  _maxDepth?: number;
  /** Date 基准时间轴（默认 2026-01-01T00:00:00Z） */
  _dateBase?: Date;
}
```

#### 3.1.2 默认值生成规则

| kind | 默认值 | 实现 |
|------|--------|------|
| `string` | `"mock-{field}"`（`isId` 字段自增） | 字符串拼接；id 类用 per-factory counter |
| `number` | 固定种子序列（可复现） | LCG：`seed = (seed * 1664525 + 1013904223) & 0xFFFFFFFF` |
| `boolean` | `false` | 固定值 |
| `date` | 固定时间轴递增 | `new Date(base.getTime() + counter * 1000)`，输出 **Date 实例**（非字符串） |
| `enum` | 第一个成员 | `_enums[field]?.[0]` 或 `schema.enumValues[0]` |
| `array` | `[]` | 空数组 |
| `object` | 递归生成 | 对 `schema.fields` 每个 key 递归调用 `generateValue` |
| 未知类型 | `undefined` | 不生成 |

#### 3.1.3 循环引用防护（Oracle 补充）

```typescript
function generateValue(field, schema, depth, rng): unknown {
  // 深度耗尽 → 返回 undefined，防止 User ↔ Post 无限递归
  if (depth > maxDepth) return undefined;
  // ...按 schema.kind 分支
}
```

#### 3.1.4 枚举/Union 识别（Oracle 修正）

- **禁止**编译时条件类型 `(T extends { enum: infer E } ? ...)` — 运行时无法执行
- **改为** `_enums` 配置项（运行时值数组），`make()` 时取 `_enums[field][0]`

#### 3.1.5 使用示例（Oracle 修订版）

```typescript
// 消费端：codegen 生成 DTO 类型 + 轻量 schema（或 Agent 手写）
const paymentFactory = createMockFactory<PaymentLog>({
  _types: {
    id: { kind: "string", isId: true },
    status: { kind: "enum" },
    amount: { kind: "number" },
    createdAt: { kind: "date" },
    items: { kind: "array", element: { kind: "object", fields: { sku: { kind: "string" } } } },
  },
  _enums: { status: ["DRAFT", "PROCESSING", "SUCCESS"] },
  _seed: 42,
});

paymentFactory.make({ status: "SUCCESS" });
// → { id: "mock-1", status: "SUCCESS", amount: <lcg(42)>, createdAt: <Date 2026-01-01>, items: [] }
```

#### 3.1.6 isIdField 严格匹配（Oracle 修正）

- 默认仅严格匹配 `field === "id"`
- 其余 id 类字段（`userId`、`paymentId`）由用户显式 `_types: { userId: { kind: "string", isId: true } }` 标记
- **避免** `endsWith("id")` 启发式误判（`grid`/`bid`）

### 3.3 createMockDb 查询语义

**FilterInput 解析**：

```typescript
// 输入结构（由 codegen 生成 TS 类型定义）：
interface PaymentLogFilterInput {
  eq?: string;
  neq?: string;
  contains?: string;
  gt?: string | number | Date;
  gte?: string | number | Date;
  lt?: string | number | Date;
  lte?: string | number | Date;
  in?: string[];
  nin?: string[];
  and?: PaymentLogFilterInput[];
  or?: PaymentLogFilterInput[];
}

// 过滤逻辑：逐行遍历内存表，递归 matchRow
// 叶子谓词（eq/neq/contains/gt/...）与 and/or 子树之间是【隐式 AND】（GraphQL 惯例）
function matchRow(row: T, filter: FilterInput): boolean {
  // 1. 先评估叶子谓词
  if (!evaluateLeafPredicates(row, filter)) return false;
  // 2. 再评估 and/or 子树
  if (filter.and && !filter.and.every((f) => matchRow(row, f))) return false;
  if (filter.or && !filter.or.some((f) => matchRow(row, f))) return false;
  return true;
}

// 混合类型比较：统一处理 Date 实例 / ISO 字符串 / number / string
function compareValues(a: unknown, b: unknown): number {
  if (a instanceof Date && b instanceof Date) return a.getTime() - b.getTime();
  if (typeof a === "string" && typeof b === "string") return a.localeCompare(b);
  if (typeof a === "number" && typeof b === "number") return a - b;
  return String(a).localeCompare(String(b)); // 跨类型 → 转字符串
}
```

> **嵌套深度限制**：and/or 递归深度 ≤ 5 层，超过抛清晰错误（防消费端递归定义栈溢出）。

**SortInput 解析**：

```typescript
interface PaymentLogSortInput {
  id?: "asc" | "desc";
  createdAt?: "asc" | "desc";
  amount?: "asc" | "desc";
}

// 多字段排序：按声明顺序逐字段比较
// [{ createdAt: "desc" }, { id: "asc" }] → 先按 createdAt 降序，同值再按 id 升序
```

**分页双模式**：

```typescript
// 【游标模式 (first/after) — Oracle 修订版】
// 游标编码：base64(JSON.stringify({ id: row.id, sortValue: row[sortField] }))
// 优点：数据插入/删除后游标不漂移（基于行身份而非索引）
function encodeCursor(row, sortField): string {
  return base64(JSON.stringify({ id: row.id, sortValue: row[sortField] }));
}
function decodeCursor(cursor: string): { id: string | number; sortValue: unknown } {
  return JSON.parse(fromBase64(cursor));
}

// after 解码 → 在已排序列表中二分定位该行 → 返回后续行
// 降级处理：游标指向的行已被删除 → 从该位置之后的第一行开始

// 【偏移模式 (page/size)】
// page: 2, size: 10 → 取第 11-20 条
```

### 3.4 状态同步（核心机制）

```typescript
// 注册 mutation handler → 写入表 → 同一 MockDb 上的 query handler 立即可见
const db = createMockDb({ paymentLogs: [] });

// 注册查询
db.registerQuery("paymentLog", "paymentLogs");

// 注册变更
db.registerMutation("createPaymentLog", "paymentLogs", "create");

// 使用：MockTransport 的 handler 内调用 db.insert()
// 后续 query("paymentLogs") 立即返回新数据

// 关键实现：
// - registerMutation 将 field 映射到表
// - MockTransport 分发时，handler 通过闭包访问 db 实例
// - db.insert() 写入后，db.query() 从同一内存表读取
```

> **reset 语义（Oracle 补充）**：`reset()` 只重置**数据**（回到种子状态），**保留** field→table 结构性映射（schema 级）。
> 重复 `registerQuery/registerMutation` 同一 field → 后者覆盖前者（覆盖策略需显式定义并在测试中验证）。
