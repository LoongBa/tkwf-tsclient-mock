## 一、背景与目标

### 1.1 现状

v1.3.0（录制回放）已可用：
- `MockFieldSchema`：7 种 kind（string/number/boolean/date/enum/array/object），枚举 + 嵌套 + isId
- `validateMock`：手写 switch 校验 — 对 7 种 kind 逐一做类型检查，返回字符串错误列表
- `selfHealing`：`validate` 注入点可插拔校验器，默认绑定 `validateMock`
- `createMockFactory`：`_types` 驱动递归生成默认值
- codegen 生成 `XxxSchema = { kind: "string", ... } as const` 字面量常量

**缺口**：
1. `validateMock` 是**手写校验**，覆盖不全（无 min/max/pattern/格式校验），漏检率随 schema 复杂度上升
2. 错误信息是**人工可读字符串**，消费端/Agent 无法结构化处理（无 path 数组、无 issue code）
3. 校验结果与工厂生成**脱节**（工厂产出 Date 实例，DTO 契约是 string——不一致未被校验层发现）
4. 无**格式校验**（email/url/uuid/datetime 格式），现有 validateMock 仅检查 typeof

### 1.2 目标

1. **zod 运行时校验**：`MockFieldSchema → zod schema` 适配器（`mockFieldSchemaToZod`），7 种 kind 递归映射
2. **validateMock 迁移**：底层切换到 zod（`safeParse`），保持 `ValidateResult` 输出签名不变，错误信息增强为结构化格式
3. **selfHealing 增强**：`selfHealing` 的 validate 注入点接收 zod 校验器，错误信息含 path/issue code
4. **codegen 运行时校验骨架**：生成产物新增 `validateZod(xxxSchema)` 辅助函数入口（可选，消费端调用）
5. **Date 语义对齐**：`kind: "date"` 映射为 `z.union([z.iso.datetime(), z.date()])`——兼容契约侧 string 和工厂侧 Date
6. **向后兼容**：`validateMock` 签名不变、`selfHealing` 签名不变、codegen 产物现有骨架不变

### 1.3 不做什么

- ❌ 不改 codegen 生成 `z.object({...})` 字面量（路径 A：适配器模式，不改模板）
- ❌ 不改 `MockFieldSchema` 类型定义（保持工厂/校验/生成的统一 schema 描述）
- ❌ 不引入 JSON Schema 中间层（7 个 kind 直接映射到 zod，无需中间转换）
- ❌ 不修改 `createMockFactory` 的 Date 产出行为（v1.4.0 仅校验层，不改工厂）
- ❌ 不添加 `zod` 的 `min/max/pattern` 等额外约束（现有 `MockFieldSchema` 无这些字段，后续版本可扩展）

## 三、方案设计

### 3.0 设计决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 映射模式 | **适配器** `mockFieldSchemaToZod(schema)` 运行时转换（不改 codegen 模板） |
| 2 | zod 版本 | **v4（`zod@^4.0.0`）** |
| 3 | Date 映射 | **`z.union([z.iso.datetime(), z.date()])`** — 兼容契约 string + 工厂 Date |
| 4 | 依赖策略 | **peerDependencies** `^4.0.0` + devDependencies |
| 5 | 空 enum 处理 | **降级 `z.string()`** — 对齐现有放行语义 |
| 6 | 缺失字段 | **`.partial()`** — 对齐现有跳过缺失字段语义 |

### 3.1 zod 适配器（`src/zod.ts` 新建）

```typescript
import * as z from "zod";
import type { MockFieldSchema } from "./factory.js";

/**
 * MockFieldSchema → zod ZodType 递归转换。
 * 保留现有 validateMock 语义：
 * - undefined 不报错 → 顶层包装 `.optional()`
 * - object 缺失字段不报错 → `.partial()`
 * - 空 enumValues 放行 → 降级 z.string()
 */
export function mockFieldSchemaToZod(schema: MockFieldSchema): z.ZodType {
  // 顶层：undefined 不报错（对齐现有语义）
  const base = toZod(schema);
  return base.optional();
}

function toZod(schema: MockFieldSchema): z.ZodType {
  switch (schema.kind) {
    case "string":  return z.string();
    case "number":  return z.number();
    case "boolean": return z.boolean();
    case "date":    return z.union([z.iso.datetime(), z.date()]);
    case "enum":
      return schema.enumValues && schema.enumValues.length > 0
        ? z.enum(schema.enumValues as [string, ...string[]])
        : z.string(); // 空 enumValues = 未填充，放行
    case "array":
      return schema.element
        ? z.array(toZod(schema.element))
        : z.array(z.unknown());
    case "object": {
      const fields = Object.fromEntries(
        Object.entries(schema.fields ?? {}).map(([k, v]) => [k, toZod(v)]),
      );
      return z.object(fields).partial(); // 缺失字段不报错
    }
  }
}

/** 便捷校验：使用 zod safeParse 校验数据，返回符合现有 ValidateResult 格式 */
export function validateWithZod(schema: MockFieldSchema, data: unknown): {
  ok: boolean;
  errors: string[];
  issues?: z.ZodIssue[];
} {
  const zodSchema = mockFieldSchemaToZod(schema);
  const result = zodSchema.safeParse(data);
  if (result.success) return { ok: true, errors: [] };
  return {
    ok: false,
    errors: result.error.issues.map(
      (i) => `${i.path.length > 0 ? i.path.join(".") : "$"}: ${i.message}`,
    ),
    issues: result.error.issues,
  };
}
```

### 3.2 validateMock 迁移（`src/ai/index.ts` 修改）

**现有 `validateMock` 签名不变**，内部实现切到 zod：

```typescript
export function validateMock(data: unknown, schema: MockFieldSchema, path = "$"): ValidateResult {
  // 新实现：委托给 mockFieldSchemaToZod + safeParse
  const zodSchema = mockFieldSchemaToZod(schema);
  const result = zodSchema.safeParse(data);
  if (result.success) return { ok: true, errors: [] };
  return {
    ok: false,
    errors: result.error.issues.map((issue) => {
      const p = issue.path.length > 0 ? `${path}.${issue.path.join(".")}` : path;
      return `${p}: ${issue.message}`;
    }),
  };
}
```

**行为变化**（需测试验证 + 文档标注）：
| 场景 | 旧行为 | 新行为 | 影响 |
|------|--------|--------|------|
| string 收到数字 | `${path}: 期望 string，实际 number` | `${path}: Expected string, received number` | 措辞英文 |
| enum 值不在范围 | `${path}: 期望枚举值之一 [a,b]，实际 c` | `${path}: Invalid enum value. Expected 'a' \| 'b', received 'c'` | 措辞英文 |
| number 收到 NaN | `${path}: 期望 number，实际 NaN` | `${path}: Expected number, received nan` | 措辞英文 |
| object 额外字段 | 不报错 | 不报错（`.partial()`） | 不变 |
| undefined | 不报错 | 不报错（`.optional()`） | 不变 |
| 空 enumValues | 放行 | 放行（降级 z.string()） | 不变 |

**整体影响**：`ValidateResult` 签名不变，错误消息措辞从中文变英文（`issues[i].message` 是 zod 默认英文）。`selfHealing` 完全不受影响（仅消费 `errors: string[]`）。

### 3.3 selfHealing 增强

**改动最小**：`selfHealing` 的 `validate` 注入点已可插拔（`validate?: (d) => ValidateResult`），默认行为不变。

**新增可选**：`selfHealing` 的 `options` 增加 `zodSchema?: MockFieldSchema`，传入时用 `validateWithZod` 校验（比默认 `validateMock` 更精确）：

```typescript
export async function selfHealing<T>(options: {
  schema: MockFieldSchema;
  zodSchema?: MockFieldSchema;  // 可选：传入时用 zod 校验
  generator?: () => unknown | Promise<unknown>;
  maxRetries?: number;
  validate?: (d: unknown) => ValidateResult;
}): Promise<T> {
  const effectiveValidate = options.zodSchema
    ? (d: unknown) => validateWithZod(options.zodSchema!, d)
    : options.validate ?? ((d: unknown) => validateMock(d, options.schema));
  // ... 现有重试逻辑不变
}
```

### 3.4 codegen 运行时校验骨架（`src/codegen/templates.ts` 扩展）

生成产物在 `XxxSchema` 常量后新增可选校验函数入口（消费端主动调用，不是自动运行）：

```typescript
// ── 运行时校验辅助（v1.4.0） ──
export function validatePaymentLog(data: unknown) {
  // 运行时导入 zod 校验器
  return import("@tkwf/tsclient-mock").then(({ mockFieldSchemaToZod }) => {
    const schema = mockFieldSchemaToZod(PaymentLogSchema);
    return schema.safeParse(data);
  });
}
```

**改动**：
- `templates.ts`：新增 `validateZodHelper(schemaName: string)` 模板
- `generate.ts`：在 `dtoTypeSchemas` 块后追加校验辅助函数块

**可选策略**：生成的是 `import(...)` 动态导入（零成本，消费端不调用则不加载 zod），或静态导入。**推荐：静态导入**（`import { mockFieldSchemaToZod } from "@tkwf/tsclient-mock"`），因为 codegen 产物已静态导入包，多一个导入开销可忽略。

## 五、审核要点

1. **向后兼容**：`validateMock` 签名不变、行为仅错措辞从中文变英文——是否影响消费端依赖错误消息文本匹配的测试？
2. **Date 语义**：`z.union([z.iso.datetime(), z.date()])` 是否覆盖所有现有 `isDateLike` 场景（ISO string / Date 实例 / 时间戳 number）？
3. **空 enum 降级**：`z.string()` 是否与现有 `enumValues 为空时跳过校验` 语义一致——空字符串是否合法通过？
4. **性能**：`mockFieldSchemaToZod` 每次调用创建新 zod schema 对象是否有可接受的开销？是否需要缓存？
5. **peerDependency 安装**：消费端没装 zod 时，`mockFieldSchemaToZod` 被调用时是否抛友好错误？
6. **codegen 产物**：`validateZod` 辅助函数是静态导入 vs 动态导入——哪种对消费端更友好？
7. **错误信息中文→英文**：`validateMock` 的 errors 从中文变英文，`selfHealing` 的 `generator`（LLM 填充）依赖错误消息文本时是否受影响？
