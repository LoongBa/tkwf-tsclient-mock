## 一、背景与目标

### 1.1 现状

v1.6.0（关联过滤嵌套）已可用：
- `registerRelation`：`hasMany`/`belongsTo` 关系注册
- `some`/`every`/`none`：关联过滤操作符（Prisma 语义）
- `matchRow` 闭包内 + `evaluateRelationFilter`：惰性 FK 查找关联解析

**缺口**：
1. **外键需手动维护**：插入日志时设 `merchantId` 不会自动更新 `merchant.logIds`；删除日志时不会清理 `merchant.logIds` 中的残留 ID
2. **关系需手动注册**：codegen 无法从 DTO 类型自动推断实体关联，消费端需手写 `registerRelation`
3. **无聚合过滤**：无法表达 `count > 5` 或 `avg(score) > 80` 这种聚合值过滤

### 1.2 目标

1. **双向同步（inverse）**：`insert`/`update`/`remove` 时自动同步 inverse 外键数组（MirageJS 3 阶段模式），`RelationDef` 新增 `inverse?: string` 字段
2. **codegen 关系推导**：`parseDtoSchemas` 二次扫描推断 DTO 间关联（`Merchant[]` → hasMany，`Merchant` 引用 → belongsTo），生成 `registerRelation` 骨架
3. **聚合过滤**：`db.aggregate(table, { fields: { ... }, where: { ... } })` 独立方法，支持 count/avg/sum/max/min + Hasura 式聚合 predicate
4. **向后兼容**：不提供 `inverse` 时行为不变（手动 FK 维护）；codegen 新增骨架为可选；`query` 签名不变

### 1.3 不做什么

- ❌ 不做自动级联删除（`dependent: "destroy"`——MirageJS 选项，后续版本）
- ❌ 不做 `bool_and`/`bool_or`/`stddev`/`variance`（低使用率聚合函数，后续版本）
- ❌ 不做 automigrate 式关系推断（只从 DTO 类型推断，不从运行时数据推断）
- ❌ 不改 `query` 签名（聚合用独立 `aggregate` 方法）
- ❌ 不改 `mock-db.test.ts` 已有的 insert/update/remove 行为（inverse 仅在 relation 注册后生效）

### 3.1 RelationDef 扩展（inverse 字段）

```typescript
export interface RelationDef {
  type: RelationType;
  targetTable: string;
  foreignKey: string;
  /** 双向同步：对方关系定义的 field 名（可选，提供时自动同步 inverse FK 数组） */
  inverse?: string;
}
```

**示例**：
```typescript
db.registerRelation("logs", "merchant", {
  type: "belongsTo",
  targetTable: "merchants",
  foreignKey: "merchantId",
  inverse: "logs",  // merchants.logs 的 field 名
});
db.registerRelation("merchants", "logs", {
  type: "hasMany",
  targetTable: "logs",
  foreignKey: "logIds",
  inverse: "merchant",  // logs.merchant 的 field 名
});
```

### 3.2 Inverse 3 阶段同步（嵌入 insert/update/remove）

**内部函数**（在 `createMockDb` 闭包内，直接在 `insert`/`update`/`remove` 中调用）：

```typescript
/** 插入后同步 inverse（Oracle 审查 🔴 B2：不可变更新，不 in-place 变异） */
function syncInverseAfterInsert(table: string, id: string | number, row: Record<string, unknown>): void {
  const tableRelations = relationRegistry.get(table);
  if (!tableRelations) return;
  for (const [field, rel] of tableRelations) {
    if (!rel.inverse) continue;
    const fkValue = row[rel.foreignKey];
    if (fkValue === undefined || fkValue === null) continue;

    if (rel.type === "belongsTo") {
      // 从目标表查询 inverse relation（Oracle 审查 🔴 B1：正确注册表）
      const targetRelations = relationRegistry.get(rel.targetTable);
      const inverseRel = targetRelations?.get(rel.inverse);
      if (!inverseRel) continue;

      const inverseTable = tables.get(rel.targetTable);
      if (!inverseTable) continue;
      const inverseRow = inverseTable.get(fkValue as string | number);
      if (!inverseRow) continue;

      // 不可变更新：造新数组，Map.set 新对象（不 in-place 变异，防快照泄漏）
      const currentArray = inverseRow[inverseRel.foreignKey] as (string | number)[] | undefined;
      const newArray = currentArray
        ? currentArray.includes(id) ? currentArray : [...currentArray, id]
        : [id];
      inverseTable.set(fkValue as string | number, { ...inverseRow, [inverseRel.foreignKey]: newArray });
    }
    // hasMany 的 inverse 同步：插入父行时需同步子行的 belongsTo FK
    if (rel.type === "hasMany") {
      const targetRelations = relationRegistry.get(rel.targetTable);
      const inverseRel = targetRelations?.get(rel.inverse);
      if (!inverseRel) continue;

      const fkArray = Array.isArray(fkValue) ? (fkValue as (string | number)[]) : [];
      const targetTable = tables.get(rel.targetTable);
      if (!targetTable) continue;
      for (const childId of fkArray) {
        const childRow = targetTable.get(childId);
        if (childRow) {
          targetTable.set(childId, { ...childRow, [inverseRel.foreignKey]: id });
        }
      }
    }
  }
}
```

**3 阶段同步（MirageJS 模式，Oracle 审查 🔴 B2：不可变更新）**：

```
insert(table, row):
  → 现有插入逻辑（造新对象 { ...row }）
  → syncInverseAfterInsert(table, id, row)  — 不可变更新（Map.set 新对象，不 in-place 变异）

update(table, id, patch):
  → 读取现有行（oldRow）
  → 对于每个有 inverse 的 belongsTo 关系：
    仅当 rel.foreignKey in patch 且 patch[fk] !== oldRow[fk] 时（Oracle 🟡 S2：用 in 判定）：
      1. disassociate：从旧 inverse 的 FK 数组中移除 id（不可变更新）
      2. associate：向新 inverse 的 FK 数组中追加 id（不可变更新）
  → 执行现有合并逻辑（造新对象 { ...existing, ...patch }）

remove(table, id):
  → 读取现有行（row）
  → 对于每个有 inverse 的 belongsTo 关系：
    从 inverse 的 FK 数组中移除 id（不可变更新）
  → 执行现有删除逻辑
```

**防循环**：`inverseTable.set(id, newRowObject)` 直接替换 `tables` Map 中的行对象，不触发 `insert`/`update`/`remove`，避免递归。配合不可变更新（永远不 in-place 变异行对象或数组），保证 `snapshots`/`datasetSnapshots` 的快照隔离不被破坏。

### 3.3 codegen 关系推断（parseDtoSchemas 二次扫描）

**推断规则（Oracle 审查 🔴 B4：FK 字段门控判定嵌入 vs 关联）**：

| DTO 字段类型 | 推断关系 | 条件 |
|-------------|---------|------|
| `Merchant`（直接引用 DTO） | `belongsTo` | 引用类型名在 `dtoSchemaMap` 中 + **源 DTO 存在 `<目标名小写>Id` 外键字段**（如 `merchantId`） |
| `Merchant[]` / `Array<Merchant>` | `hasMany` | 元素类型在 `dtoSchemaMap` 中 + **目标 DTO 存在 `<源名小写>Id` 外键字段**（如 `logs` 表有 `merchantId`） |
| 无 FK 字段的 DTO 引用 | **不推断（视为嵌入 embed）** | 无外键信号 → 不是关联 |
| 非 DTO 类型（string/number/Date） | 不推断 | — |

**关键判定（Oracle 审查 🔴 B4）**：`Merchant` 类型引用可能是**嵌入对象**（denormalized，数据在父行内）也可能是**关联**（只存 FK，数据在另一表）。唯一可靠信号是**外键字段存在性**——源 DTO 有 `merchantId` 字段时才推断 belongsTo。`sample.g.ts` 的 `Merchant.children?: Merchant[]`（自引用数组）无 FK 字段 → **不推断**（避免误判嵌入为关联）。

**输出格式（Oracle 审查 🔴 B3：独立返回，不混入 DtoSchemaMap）**：

```typescript
// 独立函数，返回关系推断列表（不污染 DtoSchemaMap 类型）
export interface DtoRelationInference {
  sourceDto: string;       // 源 DTO 名
  field: string;           // 源 DTO 中的字段名
  type: RelationType;      // "belongsTo" | "hasMany"
  targetDto: string;       // 目标 DTO 名
  fkField: string;         // 外键字段名（已推断）
}

export function inferDtoRelations(dtoSchemas: DtoSchemaMap): DtoRelationInference[];
```

### 3.4 聚合过滤

```typescript
/** 聚合函数 */
export type AggregateFunction = "count" | "avg" | "sum" | "max" | "min";

/** 聚合字段定义 */
export interface AggregateField {
  function: AggregateFunction;
  /** 聚合字段名（count 不需要，avg/sum/max/min 需要） */
  field?: string;
  /** 聚合前过滤（可选，Hasura 风格） */
  filter?: FilterInput;
  /** 聚合结果 predicate（可选，不提供时返回聚合值，提供时用 `_gt/_gte/_lt/_lte/_eq` 过滤） */
  predicate?: Record<string, number>;  // { _gt: 5, _lte: 100 }
}

/** 聚合输入 */
export interface AggregateInput {
  fields: Record<string, AggregateField>;  // 输出字段名 → 聚合定义
  where?: FilterInput;                     // 整体过滤
}

/** 聚合结果 */
export type AggregateResult = Record<string, number>;

// MockDb 接口新增方法
aggregate(table: string, input: AggregateInput): AggregateResult;
```

**示例**：
```typescript
// 查询日志表：总金额、平均金额、最大金额、status=SUCCESS 的记录数
const result = db.aggregate("logs", {
  fields: {
    totalAmount: { function: "sum", field: "amount" },
    avgAmount: { function: "avg", field: "amount" },
    maxAmount: { function: "max", field: "amount" },
    successCount: { function: "count", filter: { status: { eq: "SUCCESS" } } },
  },
});
// 结果: { totalAmount: 825, avgAmount: 165, maxAmount: 500, successCount: 3 }
```

**聚合 predicate（Oracle 审查 🔴 B5：删除 aggregatePredicate 示例，关联内聚合过滤延后）**：

聚合 predicate 功能（在 `some/every/none` 中使用聚合值过滤）**不在 v1.7.0 范围**——`aggregate` 方法只返回聚合值，不参与 `matchRow` 过滤引擎。`some/every/none` 与聚合过滤的组合留待后续版本。

**注意**：聚合 predicate 命名使用 `gt/gte/lt/lte/eq/neq`（与现有 `FilterPredicate` 一致，无下划线——Oracle 🟡 S3）。

**实现**：`aggregate` 方法内部：
1. 读取 `tables.get(table)` 获取行
2. 应用 `where` 过滤（调用 `matchRow`）
3. 对每行计算 `fields` 中定义的聚合值
4. 返回 `{ fieldName: value }` 对象
