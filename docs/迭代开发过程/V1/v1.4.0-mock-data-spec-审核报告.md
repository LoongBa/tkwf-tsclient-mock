## 代码质量评估

### 1. mock-data-spec.ts（795 行）

**优点**：
- 类型定义清晰，文档注释完整（管线描述、函数签名、参数说明）
- `parseMockDataSpec` 校验全面：version/entities/count/fields/kind/strategy/distribution/weights/scenarios
- `generateFromSpec` 生成管线正确：拓扑排序（Kahn 算法）→ 逐实体生成 → 后处理
- FK 引用通过 `idPool` 实现，拓扑排序保证父实体先于子实体生成
- `computed` 使用结构化表达式（无 `eval`），支持嵌套（`expr` 字段引用子表达式）
- `nullable` 使用确定性哈希（`hashString` + `lcgNext`），种子固定时可复现
- `weighted` 分布实现正确（归一化权重 + 累积分布索引）
- 浏览器安全函数（`serializeDatasetSeed`/`parseDatasetSeed`）无 Node 依赖

**问题**：
- `MockStrategy` 类型未导出为独立 union（`strategy: string` 缺乏类型约束）——轻微
- `MockComputeOperand` 未导出为独立接口（内联在 `MockComputeExpr.operands`）——轻微

### 2. dataset-io.ts（43 行）

**优点**：
- 简洁，每个函数职责单一
- `exportDatasetSeed` 正确处理父目录创建（`mkdirSync({recursive: true})`）
- `importDatasetSeed` 复用 `parseDatasetSeed` 的校验逻辑
- `loadMockDataSpec` 包装 `parseMockDataSpec` 添加文件 I/O

**无问题**。

### 3. factory.ts 修改（-54 +27）

**优点**：
- 4 张硬编码表全部移除，替换为外部 JSON 加载
- `resolveFieldStrategy` 的 inline regex 改为 `REGEX_STRATEGIES` 数组遍历
- `generateValue` 中 `CUSTOM_STRATEGIES` 函数调用改为 `switch` 分派（range/cycle/dateAdvance/null）
- 向后兼容：所有 helper 函数（`numberInRange`/`advanceDate`/`cycleNext`/`applyFakerMethod`）不变

**注意**：
- `discount`/`rate` 字段行为变化：旧代码 `numberInRange(ctx, 0, 100) / 100`（返回 0-1），新代码 `numberInRange(ctx, 0, 100)`（返回 0-100）。无测试覆盖此场景，实际影响面小（realistic 策略仅在显式传 `_faker` 时生效）。

### 4. 测试（442 + 111 行）

**覆盖**：
- `parseMockDataSpec`：10 个用例（合法/非法 JSON、缺失字段、非法值、边界值）
- `generateFromSpec`：9 个用例（基本生成、FK 引用、computed、nullable、weighted、sequence、回退、schemas、确定性）
- `serializeDatasetSeed`：2 个用例（pretty/compact）
- `parseDatasetSeed`：5 个用例（合法/非法 JSON、结构校验）
- 往返测试：1 个用例
- `dataset-io`：7 个用例（文件读写、错误处理、目录创建）

**缺口**：`gaussian` 降级未单独测试（已包含在 nullable 测试中，但未显式验证 console.warn 调用）

## 建议

1. **（可选）导出 `MockStrategy` 类型**：`export type MockStrategy = "sequence" | "uuid" | "ref" | "faker" | "range" | "dateRange" | "pattern" | "computed" | "constant" | "sample" | "enum"`，供消费端显示约束
2. **（可选）修正 `discount`/`rate` 行为**：如需要保留旧的 `/100` 行为，可在 `faker-method-map.json` 中改为 `{ "strategy": "range", "min": 0, "max": 1 }` 并在 `faker-method-map.ts` 中保持 `min: 0, max: 1`（当前为 0-100）。但根据 ADR09 的 `faker-method-map.json` 设计，`min/max` 表示原始范围，不包含业务变换，当前行为更准确
3. **（后续）`gaussian` 警告测试**：可在后续版本中增加 `vitest.spyOn(console, "warn")` 验证
