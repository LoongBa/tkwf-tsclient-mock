## 代码质量评估

### mock-data-spec.ts（834 行，+39 净增）

**优点**：
- `resolveScenarioCounts` 职责单一：默认 count 初始化 → 场景覆盖 → 未知场景报错，逻辑清晰
- 错误信息友好：未知场景列出可用场景列表（`可用场景：default, minimal`），无场景时明确提示
- 管线拆分干净：`applyComputed` / `applyNullable` 各司其职，注释标注 ①②③④ 顺序，可读性优于原 `applyPostPass` 合并循环
- 头部注释同步更新（管线 4 步描述），`GenerateFromSpecOptions.scenario` 标注 v1.4.1 新增
- 测试用例设计精准：constant 占位 -1 的技巧能明确区分"修复前（computed 先执行读到 -1）"与"修复后（读到 relation 值）"，回归防护有效

**问题**：无阻断性/主要问题。

**观察（不阻塞）**：
- `applyComputed` 的 `entityName` 参数已移除（仅 nullable 需要），签名精简正确
- 场景语义与 `createScenarioContext` 的区分在文档中已明确（生成期 vs 运行时），避免概念混淆

### 测试（+9 用例，36 用例/文件）

**覆盖**：
- 场景生成：完整覆盖 / 部分覆盖 / empty / 未知场景 / 无场景 / 确定性（6 用例）
- 管线修正：computed-FK 引用 / nullable-FK 置空（2 用例）
- parse 校验：场景实体名存在性（1 用例）

**缺口**：`scenario` 与 `faker` 参数组合未单独测试（实现上正交，风险低）；`empty` 场景下子实体 relation 的 warn 输出未断言（仅断言不抛错）——可接受，非阻塞。
