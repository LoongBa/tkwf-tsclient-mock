## 一、背景与目标

### 1.1 现状

当前 Agent 填充 mock 数据需要手动拼接三处信息：

1. `ts-client.mock.g.ts` 的 `createMockDb` 表名 ← 代码生成，但 Agent 不知道每张表影响哪些 API
2. 每张表填什么字段 ← 需要去 `schema.graphql` 查 DTO 定义
3. 每张表填多少条、取什么值 ← 没有数据策略文档

**已提交的前序修复**：
- `MockTransport.execute` 按 GraphQL 契约包裹 `{ [field]: result }`（`a628db0`，随 v1.3.0 发布）

**不在此版本范围内**：
- `@tkwf/tsclient v1.0.6` GraphQL_Api.md DTO 字段展开（tsclient 仓库独立迭代，本版本不依赖）

### 1.2 目标

1. **`ts-client.mock.g.ts` 的 `// → API:` 反向注释**：`createMockDb` 表名后标注影响的 API field 列表
2. **`gen-mock-handlers --mock-spec`**：自动生成 `MOCK_SPEC.md` 的 API 映射表
3. **MOCK_SPEC.md 模板**：框架提供可复用的数据策略模板（含填写说明），项目实例化
4. **`tkwf-tsclient-mock` skill 文件**：指导 Agent 从读取文档到填充 `data.ts` 的完整流程

## 二、功能设计

### 2.1 `ts-client.mock.g.ts` 的 `// → API:` 反向注释

**已在工作区实现**，作为 v1.3.0 开发产出。

**改动**：
- `src/codegen/generate.ts`：新增 `collectTableFields()` 构建表名 → API field 列表的反向索引
- `src/codegen/templates.ts`：`dbSkeleton()` 新增 `tableToFields` 参数，每行表名后渲染 `// → API: field1, field2`

**效果**：
```typescript
export const db = createMockDb({
  loginPayloads: [] satisfies LoginPayload[],  // → API: loginByContext, loginByPassword, logout
  paymentLogs: [] satisfies PaymentLog[],  // → API: loadPaymentLogs
  dashboardSummaryDtos: [] satisfies DashboardSummaryDto[],  // → API: summary
  // ...
});
```

**一致性补充**：`scenariosSkeleton` 使用同样的 `tableInits`，也应加 `tableToFields` 参数生成注释。与 `dbSkeleton` 同步更新。

### 2.2 `gen-mock-handlers --mock-spec`

**CLI 参数**：

```
gen-mock-handlers --input src/gql/ts-client.g.ts --output src/gql/ts-client.mock.g.ts
                  --mock-spec .TKWF/merchant/MOCK_SPEC.md
```

- `--mock-spec` 可选参数，指定输出路径
- 输出内容：**仅 API 映射表**（即 `// → API:` 的逆映射：API → 数据表），不覆盖数据策略
- 幂等安全：如果文件已存在，检测到 `<!-- auto-generated: mapping-table -->` 和 `<!-- end-auto-generated -->` 标记段，只替换该段，保留其他章节。如果无标记，追加到文件末尾

**输出格式**：

```markdown
<!-- auto-generated: mapping-table -->
| API 操作 | 类型 | 需要的数据表 | 说明 |
|----------|------|------------|------|
| `loginByPassword` | Mutation | `loginPayloads` |  |
| `queryPaymentLogs` | Query | `paymentLogQueryResultDtos` |  |
...
<!-- end-auto-generated -->
```

**实现要点**：
- 从 `serviceMethods` 直接构建 `field → table` 映射（遍历每个 method 的 `name` + `entityType` → `entityTypeToTableName`），按 API 名（field 名）排序。
  ⚠️ **注意**：`collectTableFields()` 返回 `{ table → [field] }`（表 → API），是反向引用注释用的；MOCK_SPEC 需要 `{ field → table }`（API → 表），方向相反，需单独构建。
- 表名从 `entityTypeToTableName` 推导，与 `ts-client.mock.g.ts` 的 `createMockDb` 表名一致
- `说明` 列留空（由项目手写）

## 四、schema 变更后的同步流程

当 `schema.graphql` 变更（新增 field、新增 API、改字段类型）时，按顺序执行：

```bash
buildSchema.ps1 -Quick          # ① 更新 schema.graphql
npm run gen-ts-client            # ② 更新 ts-client.g.ts（类型 + 服务接口）
npm run gen-mock                 # ③ 更新 ts-client.mock.g.ts（新 handler 骨架 + // → API: 注释）
gen-mock-handlers --mock-spec <本文件路径>   # ④ 更新本文件第一节映射表
```

执行第③④步后：
1. `ts-client.mock.g.ts` 的 `createMockDb` 会自动新增/删除表，并更新 `// → API:` 注释
2. `--mock-spec` 幂等更新本文件第一节的 API 映射表
3. 如果新增了表，补充第二节数据策略、第三节表间关系
4. 编辑 `src/mock/data.ts` 补充新表的初始数据
```

### 2.4 MOCK_SPEC.md 的位置

**设计决策**：MOCK_SPEC.md 放在 `.TKWF/merchant/` 与 `GraphQL_Api.md` 同级。

⚠️ 注意：`.TKWF/{域}/` 目录在项目配置中为 gitignored（xCodeGen 生成文件）。这意味着：
- `MOCK_SPEC.md` 不会被 git 跟踪
- 首次使用：从模板复制 + `gen-mock-handlers --mock-spec` 生成
- 后续使用：由 `gen-mock-handlers --mock-spec` 的幂等更新机制维护

如果项目需要版本控制数据策略，可：
- 在 `.gitignore` 中加例外规则 `!.TKWF/merchant/MOCK_SPEC.md`
- 或手写的数据策略部分放在前端项目 `src/mock/MOCK_SPEC.md`，自动生成的映射表部分留在 `.TKWF/merchant/`

**本方案不做强制规定**，由各项目自行决定。

### 2.5 `tkwf-tsclient-mock` skill 文件

**位置**：`skills/tkwf-tsclient-mock/` 目录（与本包同仓库，项目通过软链接整个目录到 `.agents/skills/` 引用）

**文件结构**：

├── SKILL.md              ← skill 主文件（Agent 行为指导）
├── MOCK_SPEC.md.template ← 数据策略模板（独立文件，与 src/mock-spec/ 的模板内容保持一致）

**SKILL.md 内容**：

```markdown
# tkwf-tsclient-mock Skill

## 适用场景
为项目生成和填充 mock 数据，使前端在无后端时也能运行。

## 前置条件
- [ ] ts-client.g.ts 已生成（npm run gen-ts-client）
- [ ] ts-client.mock.g.ts 已生成（npm run gen-mock 或 start-dev.ps1 -GenMock）

## 步骤

### Step 1：初始化 MOCK_SPEC.md（首次）
如果 .TKWF/merchant/MOCK_SPEC.md 不存在：
1. 复制模板到 .TKWF/merchant/MOCK_SPEC.md
   - 模板位置（file: 本地引用）：<项目>/node_modules/@tkwf/tsclient-mock/skills/tkwf-tsclient-mock/MOCK_SPEC.md.template
   - 模板位置（npm 安装）：<项目>/node_modules/@tkwf/tsclient-mock/skills/tkwf-tsclient-mock/MOCK_SPEC.md.template
   - 或源码仓库：<tkwf-tsclient-mock>/skills/tkwf-tsclient-mock/MOCK_SPEC.md.template
2. 运行 gen-mock-handlers --mock-spec .TKWF/merchant/MOCK_SPEC.md 填充映射表
3. 根据项目需求文档（Rxx）和 DOMAIN_MAP.md 填写数据策略（第二节）
4. 根据 DOMAIN_MAP.md 实体关系填写表间关系（第三节）

### Step 2：填充 initialData
1. 读 ts-client.mock.g.ts 的 createMockDb({...}) → 拿到所有表名和 // → API: 注释
2. 读 MOCK_SPEC.md 的映射表 → 知道每张表影响哪些 API
3. 读 MOCK_SPEC.md 的数据策略 → 知道每张表填多少条、字段约束
4. 读 schema.graphql 对应 DTO 类型 → 知道字段名和类型
5. 读 DOMAIN_MAP.md 对应实体字段描述 → 知道字段含义
6. 读 Business.md 业务规则 → 知道数据间约束关系
7. 编辑 src/mock/data.ts 的 initialData，填充数据

### Step 3：验证
- npm test（确保测试通过）
- npm run dev:mock（启动后登录，逐个页面检查数据渲染）

## 工具参考
- createMockFactory<T>({ _types: XxxSchema, _strategy: "realistic" }) 生成真实感数据
- defineXxxFactory.make({ key: value }) 覆盖关键字段
- db.registerRelation() 注册外键关系
- createScenarioContext 切换场景（default/error/loading）
```
