## 一、背景与目标

### 1.1 现状

v1.0.0–v1.7.1 全部完成。现有 MockTransport 在 Transport 接口层工作，**不经过 HTTP 协议**：
- `MockTransport.execute()` 直接调用 handler，无 HTTP 请求/响应对象
- 无 status code、无 headers、无 CORS、无 body 解析
- 消费端通过 `Tkwf.configure({ transport: mockTransport })` 注入，不走 HTTP 网络

**缺口**：
1. 无法模拟真实 HTTP 语义（CORS/鉴权头/HTTP 状态码/超时/重试）
2. 消费端集成测试需要验证 HTTP 层行为（401 未认证、429 限流、500 服务器错误），当前无法做到
3. 无法与不感知 Transport 注入的第三方工具配合（如 Playwright 测试需要真实 HTTP endpoint）

### 1.2 目标

1. **基于 node:http 的轻量 HTTP server**：零外部依赖，`createServer` + 中间件链
2. **CORS 模拟**：OPTIONS 预检 + Access-Control-Allow-Origin/Headers/Methods
3. **鉴权模拟**：`Authorization: Bearer <token>` 提取 + 模拟 401/403
4. **GraphQL over HTTP**：`POST /graphql` 遵循官方规范，桥接到 `MockTransport.execute()`
5. **状态码注入**：通过 scenario/fieldOptions 配置 HTTP 状态码（200/401/429/500）
6. **生命周期**：`MockHttpServer.create()` → `listen()` → `stop()`，`port = 0` 自动分配
7. **bin 入口**：`npx mock-server` 一键启动

### 1.3 不做什么

- ❌ 不引入 Express/Koa 等外部框架（纯 node:http）
- ❌ 不做 `@types/node` 依赖（建 `src/http-mock/types.d.ts` 声明文件）
- ❌ 不做完整 HTTP 协议实现（只覆盖 GraphQL over HTTP + 基本 REST 路由）
- ❌ 不改 MockTransport 现有流程（HTTP server 是上层包装，不侵入 Transport 层）
- ❌ 不做 WebSocket/SSE（GraphQL Subscription 不在本版范围）

## 三、方案设计

### 3.0 设计决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 服务架构 | **基于 node:http 的中间件链**（零外部依赖） |
| 2 | 端口分配 | **`port = 0` 自动分配**（OS 分配空闲端口） |
| 3 | GraphQL 协议 | **遵循 graphql-over-http 规范**（POST /graphql，JSON body） |
| 4 | 类型声明 | **自建 `types.d.ts`**（声明 `node:http` 模块，替代 @types/node） |
| 5 | 鉴权方式 | **`Authorization: Bearer <token>` 提取 + 模拟 401/403** |
| 6 | 状态码注入 | **通过 scenario 配置 HTTP 状态码**（复用 `fieldOptions` 或新增 `httpStatus`） |

### 3.1 类型声明（`src/http-mock/types.d.ts`）

```typescript
declare module "node:http" {
  export interface IncomingMessage {
    method?: string;
    url?: string;
    headers: Record<string, string | string[] | undefined>;
    statusCode?: number;
  }
  export interface ServerResponse {
    statusCode: number;
    headersSent: boolean;
    setHeader(name: string, value: string): void;
    writeHead(statusCode: number, headers?: Record<string, string>): void;
    end(data?: string): void;
    on(event: string, handler: (...args: unknown[]) => void): void;
  }
  export interface Server {
    listen(port: number, hostname?: string, callback?: () => void): Server;
    close(callback?: (err?: Error) => void): void;
    address(): { port: number; family: string; address: string } | null;
  }
  export function createServer(
    requestListener?: (req: IncomingMessage, res: ServerResponse) => void,
  ): Server;
}
declare module "node:net" {
  export interface Socket {
    destroy(): void;
    on(event: string, handler: (...args: unknown[]) => void): void;
  }
}
declare module "node:url" {
  export class URL {
    constructor(url: string, base?: string);
    pathname: string;
    searchParams: URLSearchParams;
  }
}
```

### 3.2 MockHttpServer（`src/http-mock/server.ts`）

```typescript
export interface MockHttpServerOptions {
  transport: Transport;           // MockTransport 实例（必填）
  port?: number;                  // 默认 0（OS 自动分配）
  host?: string;                  // 默认 "127.0.0.1"
  cors?: boolean;                 // 默认 true
  auth?: boolean;                 // 默认 false
  delayMs?: number;               // 全局延迟模拟
}

export class MockHttpServer {
  constructor(options: MockHttpServerOptions);
  /** 启动 server，返回实际端口号 */
  start(): Promise<number>;
  /** 停止 server，销毁所有连接 */
  stop(): Promise<void>;
  /** 获取当前端口号 */
  get port(): number;
}
```

**server 内部流程**：
```
createServer(async (req, res) => {
  1. CORS middleware（OPTIONS → 204，注入跨域头）
  2. Body parser（for await...of 收集 body → JSON.parse）
  3. Auth middleware（提取 Authorization header → sessionKey）
  4. Router dispatch：
     POST /graphql → GraphQLHandler
     GET /health → { status: "ok" }
     * → 404
  5. 响应格式化 + 状态码注入
})
```

### 3.4 GraphQL Handler（`src/http-mock/graphql-handler.ts`）

```typescript
export class GraphQLHandler {
  constructor(private transport: Transport) {}

  async handle(body: GraphQLRequestBody, sessionKey: string | null): Promise<{
    status: number;
    headers: Record<string, string>;
    body: unknown;
  }>;
}

interface GraphQLRequestBody {
  query: string;
  operationName?: string;
  variables?: Record<string, unknown>;
}
```

**桥接逻辑**：
```
GraphQLHandler.handle(body, sessionKey):
  1. 从 query 提取 field 名（复用 MockTransport.extractField 逻辑）
  2. 调用 transport.execute({ field, type, variables, sessionKey })
  3. 成功 → { status: 200, body: { data: result } }
  4. 失败（MockRecordingError）→ { status: 500, body: { errors: [{ message }] } }
  5. 鉴权失败 → { status: 401, body: { errors: [{ message: "Unauthorized" }] } }
```

## 四、审核要点

1. **node:http 类型声明**：`types.d.ts` 声明了 `node:http` 模块——是否与 node 实际运行时类型一致？`ServerResponse.on()` 是否存在？
2. **端口管理**：`port = 0` 自动分配后在 `start()` 返回值中获取——`server.address()` 是否在 `listen` callback 中可用？
3. **GraphQL 错误映射**：MockTransport 抛出的 `DomainClientError` 如何映射到 HTTP 状态码（401 → 401, 429 → 429, 其他 → 500）？
4. **CORS 头大小写**：`node:http` 自动将 header 名转为小写（`Access-Control-Allow-Origin` → `access-control-allow-origin`）——浏览器是否接受小写 CORS 头？
5. **并发连接**：`stop()` 时需要先 destroy 活跃连接再 `close()`，否则 `server.close()` 不会关闭——连接追踪是否齐全？
6. **GraphQL 解析**：`MockTransport.extractField()` 的正则是否兼容所有 GraphQL query 格式（含 fragment、directive、多层嵌套）？
7. **bin 入口**：`npx mock-server` 启动时需要读取消费端的 handler 文件——CLI 参数如何设计才能让消费端无需改代码？
