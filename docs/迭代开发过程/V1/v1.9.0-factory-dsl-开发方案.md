# v1.9.0 — 工厂 DSL + buildDataset 外键校验

> **状态**：待开发（v1 草案，待 Oracle 审核）
> **版本**：v1.9.0
> **关联**：原始方案 §1.5.3（Fabbrica 式工厂 DSL）+ §3.4（buildDataset 外键一致图构建）
> **设计决策（已确认）**：1. 工厂 DSL = 最小侵入骨架（`createMockFactory<Xxx>({ _types: XxxSchema })`）；2. buildDataset FK 校验 = `strict` 可选参数（默认 false，向后兼容）

---

## 一、目标

### 1.1 工厂 DSL（defineXxxFactory 骨架）

**现状**：`createMockFactory` 已实现，但 codegen 产物只生成 `createMockDb` + `handlers`，没有 `defineXxxFactory` 工厂 DSL。

**目标**：codegen 生成 `export const defineXxxFactory = createMockFactory<Xxx>({ _types: XxxSchema })` 骨架，消费端可直接用 `defineXxxFactory.make({ status: "SUCCESS" })` 生成合法数据。

### 1.2 buildDataset 外键校验

**现状**：`buildDataset` 纯替换式写入，不校验 `relationRegistry` 中的外键定义。

**目标**：`buildDataset` 写入后遍历 `relationRegistry`，校验 `belongsTo` FK 值在目标表存在、`hasMany` 数组元素在目标表存在。发现违规时收集 violations 并抛错。

### 1.3 不做什么

- ❌ 不做 Fabbrica 式 `patcher`/`traits`（留后续版本）
- ❌ 不改 `createMockFactory` 内部实现（只改 codegen 生成）
- ❌ 不改 `buildDataset` 的批量写入性能（校验为 O(n)，对 mock 数据量可接受）

## 三、方案设计

### 3.1 工厂 DSL 骨架（templates.ts + generate.ts）

**模板函数**：

```typescript
export function factorySkeleton(dtoBlocks: Array<{ name: string; schema: string }>): string {
  if (dtoBlocks.length === 0) return "";
  const lines = dtoBlocks.map(
    (d) => `export const define${d.name} = createMockFactory<${d.name}>({ _types: ${d.name}Schema });`,
  );
  return [
    "",
    "// ── 工厂 DSL（v1.9.0，Agent 可用 defineXxxFactory.make({ key: value }) 覆盖关键字段） ──",
    ...lines,
    "",
  ].join("\n");
}
```

**imports 修改**：

```typescript
// 当前：import { createMockDb, defineMock } from "@tkwf/tsclient-mock";
// 改为：import { createMockDb, defineMock, createMockFactory } from "@tkwf/tsclient-mock";
```

**generate.ts 插入点**：

```typescript
lines.push(tpl.dtoTypeSchemas(dtoBlocks));
lines.push(tpl.factorySkeleton(dtoBlocks));  // ← 新增
lines.push(tpl.validateZodHelpers(schemaNames));
```

### 3.2 buildDataset 外键校验（mock-db.ts）

```typescript
buildDataset(dataset: DatasetSeed, options?: { strict?: boolean }): void {
  // 1. 现有写入逻辑不变
  for (const [table, rows] of Object.entries(dataset)) {
    const tableMap = tables.get(table) ?? new Map();
    for (const row of rows) {
      const id = (row.id ?? row.Id) as string | number;
      tableMap.set(id, { ...row });
    }
    tables.set(table, tableMap);
  }

  // 2. FK 校验（v1.9.0）
  if (options?.strict) {
    const violations: string[] = [];
    for (const [table, fieldMap] of relationRegistry) {
      const tableMap = tables.get(table);
      if (!tableMap) continue;
      for (const [, rel] of fieldMap) {
        const targetTable = tables.get(rel.targetTable);
        for (const [id, row] of tableMap) {
          if (rel.type === "belongsTo") {
            const fk = row[rel.foreignKey] as string | number | undefined;
            if (fk !== undefined && fk !== null && (!targetTable || !targetTable.has(fk))) {
              violations.push(
                `${table}[${id}].${rel.foreignKey}=${fk} → ${rel.targetTable}[${fk}] not found`,
              );
            }
          } else if (rel.type === "hasMany") {
            const fkArray = row[rel.foreignKey] as (string | number)[] | undefined;
            if (fkArray) {
              for (const fk of fkArray) {
                if (!targetTable || !targetTable.has(fk)) {
                  violations.push(
                    `${table}[${id}].${rel.foreignKey} contains ${fk} → ${rel.targetTable}[${fk}] not found`,
                  );
                }
              }
            }
          }
        }
      }
    }
    if (violations.length > 0) {
      throw new Error(`MockDb: buildDataset FK violations:\n- ${violations.join("\n- ")}`);
    }
  }
}
```

**为什么默认不开启**：`strict` 默认 `false`——向后兼容，消费端已有 `buildDataset` 调用不受影响。

## 四、审核要点

1. **向后兼容**：`buildDataset` 新增 `strict` 参数可选，默认 `false`——现有调用是否完全不受影响？
2. **FK 校验时机**：校验在写入**之后**执行——如果校验失败抛错，已写入的数据是否需要回滚？
3. **defineXxxFactory 类型**：`createMockFactory<Xxx>({ _types: XxxSchema })`——`XxxSchema` 是 `as const`，`_types` 期望 `Record<keyof T, MockFieldSchema>`——`as const` 的 readonly 类型是否兼容？
4. **imports 顺序**：`createMockFactory` 是运行时 import（`import { createMockDb, defineMock, createMockFactory }`），不是 type import——是否与现有 `imports()` 函数结构一致？
