## 〇、版本号

| 包 | 版本 | 说明 |

| `@tkwf/tsclient-mock` | **v1.4.3** | gen-seed CLI + importDatasetSeed unknownTables 透传 + HTTP 状态语义示例 + defaultSessionHandlers 补齐 4 个缺漏 handler |

**版本决策**：v1.4.2 交付后，项目组实践反馈 + 差集分析确认 4 项缺口：
1. 消费端需手动写脚本导出 `seed.json`（给其他项目做模式 A 交接）——建议内置 `gen-seed` 工具
2. `importDatasetSeed` 没有透传 `unknownTables` 选项，Node 端接收方检测表名不匹配需两步走
3. G07D §4.8 仅说明"单 Transport 共享状态"，未给出多客户端并发 mutation 可见性示例
4. `defaultSessionHandlers` 差集分析发现 4 个主包标准方法缺 mock handler（`loginBySms` / `ping` / `registerSecure` / `loginByQrCode`）——消费端调用这些方法时 mock 抛"no handler"

四者均为纯增量（新增 handler / 新增 CLI / 新增可选参数 / 文档补充），patch 发布（v1.4.3）。

### 1.3 不做什么

- **不改 `exportDatasetSeed` 签名**：`exportDatasetSeed(db, tables, path)` 已稳定，无需变动
- **不直接支持 `--mock-spec` 输入**：gen-seed 从 `mock-data-spec.json` 读规则，不从 MOCK_SPEC.md 读——MOCK_SPEC.md 是策略文档，不是机器可读的规则
- **不改变 `generateFromSpec` 默认行为**：gen-seed 只是 `generateFromSpec` + `serializeDatasetSeed` 的 CLI 包装，不引入新生成逻辑
- **不补 `refreshToken` handler**：主包 `DomainClientUser` 源码中不存在 `refreshToken` 方法，无需补
- **不补 `query` / `mutate` handler**：这两个是通用 RPC 方法，field 值由调用方运行时动态传入，不属于静态会话 handler

## 二、技术设计

### 2.1 gen-seed CLI

#### 2.1.1 设计

新增 `src/codegen/gen-seed.ts`，作为独立 bin 入口（与 `cli.ts` 同级）。遵循 `gen-mock-handlers` 的 CLI 模式：手写参数解析、零外部依赖、Node-only。

**用法**：

```bash
gen-seed --spec <mock-data-spec.json> [--output seed.json] [--scenario default] [--faker]
```

**参数**：

| 参数 | 别名 | 默认值 | 说明 |
|------|------|--------|------|
| `--spec` | `-s` | 必填 | mock-data-spec.json 路径 |
| `--output` | `-o` | `seed.json` | 输出 seed.json 路径 |
| `--scenario` | `--sc` | 无（不传则用实体默认 count） | 生成期场景名（v1.4.1） |
| `--faker` | `-f` | 不启用 | 启用 faker 策略（需安装 `@faker-js/faker`） |
| `--help` | `-h` | — | 帮助信息 |

**内部流程**（`main()` 为 async，因 `--faker` 需动态 `import()`）：

```
readFile(specPath) → parseMockDataSpec(json)
→ if --faker: await import("@faker-js/faker") → fakerZH_CN（失败则 console.warn 降级）
→ generateFromSpec(spec, { faker?, scenario? }) → serializeDatasetSeed(seed) → writeFile(outputPath)
```

> **核心逻辑提取**：参照 `gen-mock-handlers` 模式（`index.ts` 放核心逻辑可测，`cli.ts` 放 CLI 薄壳），gen-seed 同理拆分：
> - `gen-seed-core.ts`：导出 `generateSeedFile(specPath, options)` 可测函数
> - `gen-seed.ts`：CLI 入口，解析参数 → 调用 `generateSeedFile`

#### 2.1.2 文件结构

```

├── gen-seed-core.ts    # 新增：generateSeedFile 核心逻辑（可测）
├── gen-seed.ts         # 新增：gen-seed CLI 入口（薄壳）
├── index.ts            # genMockHandlers 核心（已有）

```

### 2.2 importDatasetSeed unknownTables 透传

**当前**（`dataset-io.ts:30-34`）：

```typescript
export function importDatasetSeed(db: MockDb, filePath: string): void {
  const content = fs.readFileSync(filePath, "utf-8");
  const seed = parseDatasetSeed(content);
  db.buildDataset(seed);  // 不传 unknownTables
}
```

**目标**：

```typescript
export function importDatasetSeed(
  db: MockDb,
  filePath: string,
  options?: { unknownTables?: "warn" | "error" | "ignore" },
): void {
  const content = fs.readFileSync(filePath, "utf-8");
  const seed = parseDatasetSeed(content);
  db.buildDataset(seed, { unknownTables: options?.unknownTables });
}
```

**兼容性**：`importDatasetSeed(db, path)` 无第三个参数 → `options` 为 `undefined` → `unknownTables` 为 `undefined` → `buildDataset` 默认 `"ignore"` → 完全向后兼容。

### 2.3 G07D §4.8 多客户端状态语义示例

在现有 §4.8 的"注意"段后补充：

**多客户端并发示例**：

```typescript
// 两个客户端访问同一个 MockHttpServer
const transport = new MockTransport(handlers, { delayMs: 50 });
const server = new MockHttpServer({ transport, port: 0 });
await server.start();

// 客户端 A 插入一条数据
await fetch(`http://localhost:${port}/graphql`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ query: "mutation { createPaymentLog(input: { ... }) { id } }" }),
});

// 客户端 B 查询 → 可见客户端 A 插入的数据（共享状态）
const res = await fetch(`http://localhost:${port}/graphql`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ query: "{ paymentLogs { id } }" }),
});
const data = await res.json();
// data.data.paymentLogs.length > 0 — 包含客户端 A 插入的行
```

**说明**：单 Transport 实例 = 共享内存状态。所有客户端看到同一份数据，mutation 全局可见。适合联调/演示；若需要状态隔离（如多租户模拟），需为每个租户创建独立的 Transport 实例（或使用 `MockDb.switchDataset` 切换数据集）。

### 2.4 defaultSessionHandlers 补齐 4 个缺漏 handler

#### 2.4.1 差集分析依据

`@tkwf/tsclient` 主包 `DomainClientUser`（`domain-client-user.ts`）共有 8 个标准 field 调用（`transport.execute({ field: "..." })`）。mock 包 `defaultSessionHandlers`（`session.ts`）当前仅覆盖 4 个，差集 4 个：

| handler | 主包方法 | type | 现有 | 优先级 | 推荐 mock 返回值 |
|---------|---------|------|------|--------|-----------------|
| `loginBySms` | `loginBySms(mobile, captcha)` | mutation | ❌ | 高 | `{ success: true, userName: mobile, sessionKey: "mock-session", displayName: mobile }` |
| `ping` | `ping(sessionKey)` | mutation | ❌ | 高 | `{ success: true, isAuthenticated: true, userName: "mock-user", sessionKey: "mock-session" }` |
| `registerSecure` | `registerSecure(userName, password, options?)` | query | ❌ | 中 | `{ success: true, message: "注册成功" }` |
| `loginByQrCode` | EXPLICIT_MUTATIONS 声明（源码无实现） | mutation | ❌ | 低 | `{ success: true, userName: "mock-user", sessionKey: "mock-session" }` |

**不补的**：
- `refreshToken`：主包源码中不存在此方法
- `query` / `mutate`：field 值由调用方运行时动态传入，不属于静态会话 handler

#### 2.4.2 实现

**当前**（`session.ts`）——注意 `loginByPassword` / `loginByContext` 缺 `success` 字段：

```typescript
export const defaultSessionHandlers: Record<string, MockHandler> = {
  requestChallenge: () => ({ challengeToken: "mock-challenge", salt: "mock-salt" }),
  loginByContext: (variables) => ({ sessionKey: "mock-session", userName: (variables as { userName?: string })?.userName ?? "mock-user" }),  // ⚠️ 缺 success
  loginByPassword: (variables) => ({ sessionKey: "mock-session", userName: (variables as { userName?: string })?.userName ?? "mock-user" }),  // ⚠️ 缺 success
  logout: () => true,
};
```

**目标**（新增 4 个 handler + 修复 2 个现有 handler 补 `success: true` + `displayName`）：

```typescript
export const defaultSessionHandlers: Record<string, MockHandler> = {
  requestChallenge: () => ({ challengeToken: "mock-challenge", salt: "mock-salt" }),

  // v1.4.3 修复：补 success + displayName
  loginByContext: (variables) => ({
    success: true,
    sessionKey: "mock-session",
    userName: (variables as { userName?: string })?.userName ?? "mock-user",
    displayName: (variables as { userName?: string })?.userName ?? "mock-user",
  }),

  // v1.4.3 修复：补 success + displayName
  loginByPassword: (variables) => ({
    success: true,
    sessionKey: "mock-session",
    userName: (variables as { userName?: string })?.userName ?? "mock-user",
    displayName: (variables as { userName?: string })?.userName ?? "mock-user",
  }),

  // v1.4.3 新增：短信验证码登录
  loginBySms: (variables) => ({
    success: true,
    sessionKey: "mock-session",
    userName: (variables as { mobile?: string })?.mobile ?? "mock-user",
    displayName: (variables as { mobile?: string })?.mobile ?? "mock-user",
  }),

  // v1.4.3 新增：会话心跳
  ping: () => ({
    success: true,
    isAuthenticated: true,
    userName: "mock-user",
    sessionKey: "mock-session",
  }),

  // v1.4.3 新增：安全注册
  registerSecure: (variables) => ({
    success: true,
    message: "注册成功",
    userName: (variables as { userName?: string })?.userName ?? "mock-user",
  }),

  // v1.4.3 新增：扫码登录（防御性——主包 EXPLICIT_MUTATIONS 声明但源码无实现）
  loginByQrCode: (variables) => ({
    success: true,
    sessionKey: "mock-session",
    userName: (variables as { userName?: string })?.userName ?? "mock-user",
  }),

  logout: () => true,
};
```

#### 2.4.3 设计要点

- **`loginBySms`**：从 `variables.mobile` 取手机号作为 `userName`（与 `loginByPassword` 从 `variables.userName` 取值的模式一致），不校验 `captcha`（mock 永远放行）
- **`ping`**：固定返回 `isAuthenticated: true`——mock 模式下会话永远有效，适合测试"已登录"常态
- **`registerSecure`**：固定返回 `success: true`——mock 模式下注册永远成功
- **`loginByQrCode`**：防御性添加——主包 `EXPLICIT_MUTATIONS` 集合已声明此 field，虽然 `domain-client-user.ts` 源码中尚无对应方法实现，但消费端可能自行调用 `transport.execute({ field: "loginByQrCode" })`，提前覆盖避免 "no handler" 错误

### 3.5 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| gen-seed 的 faker 策略依赖 `@faker-js/faker`，未安装时降级 | 高 | 数据不真实但可用 | 与 `generateFromSpec` 行为一致：不传 `--faker` 时用 minimal 策略 + console.warn |
| gen-seed 作为 bin 需要编译后可用，本地开发时需 `npm run build` | 低 | 开发体验 | 与 gen-mock-handlers 约束一致，文档注明"先 `npm run build` 或 `npx tsx`" |
| `importDatasetSeed` 签名变化影响已有调用 | 低 | 编译错误 | 可选参数 `options?: { unknownTables? }`，不传则行为完全不变 |
| 新增 handler 的返回值字段与主包 `LoginPayload` / `PingResult` / `RegisterResult` 类型不匹配 | 中 | 消费端类型推断错误 | 参照主包 `domain-client-user.ts` 的 selection 字段，确保 mock 返回值含全部必要字段 |
| `loginByQrCode` 主包无源码实现，mock 返回值字段可能不准 | 低 | 未来主包实现后字段不匹配 | 防御性添加，主包实现后据实际 selection 调整；当前 mock 返回值与 `loginBySms` 同构 |
