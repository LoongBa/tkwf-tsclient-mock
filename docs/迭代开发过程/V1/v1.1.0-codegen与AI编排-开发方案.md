## 一、背景与目标

### 1.1 现状

v1.0.0（三大核心）已可用：
- `createMockFactory<T>()` 运行时 schema 驱动生成默认值
- `createMockDb()` 内存数据库：CRUD + Filter/Sort/分页 + 状态同步
- `MockTransport` 按 field 分发 handler
- `defineMock` 仅类型化占位（无类型约束能力）

**缺口**：消费端接入 mock 时仍**手工编写**每个 field 的 handler。服务端 API 有多少 field，就要手写多少 handler——这正是讨论方案 §1.5.2 差异点"完整性保证"要解决的：**codegen 生成全部 field 的 handler 骨架，Agent 不可能漏掉 API**。

### 1.2 目标

1. **codegen 扩展**：消费端运行 `gen-mock-handlers`，读取其 `ts-client.g.ts`（codegen 产物），生成 `ts-client.mock.g.ts`——全部 field 的 handler 骨架（`defineMock` 包装 + `createMockDb` 注册）
2. **AI 编排基础设施**：提供 schema 验证 / 自愈重试 / hash 变更检测的基础设施（**不内置 LLM 调用**，避免重依赖；LLM 编排留给消费端 SKILL 落地）
3. **完整性保证**：codegen 生成 = API 不可能漏掉；`satisfies` + 编译期覆盖检查 = 新增 field 缺 handler 时编译报错
4. **过滤桥接**：mock-db 增强以兼容消费端 `OperationFilterInput` 家族过滤格式（Oracle 🔴#6）

### 1.3 不做什么

- ❌ 不内置 LLM 调用（AI 编排仅提供验证/重试/变更检测基础设施）
- ❌ 不改主包 `@tkwf/tsclient`（主包 transport 注入点属另一仓库 v1.1.0，独立迭代）
- ❌ 不做 HTTP 层 mock server
- ❌ 不从 GraphQL schema 文件（`.graphql`）提取枚举值（枚举值留空由 Agent/AI 填充，见 🟡#4）

### 3.1 gen-mock-handlers 输入：真实消费端 codegen 产物结构（Oracle 实测）

真实 `ts-client.g.ts`（主包 v1.0.5 泛型化后，2900+ 行）的关键结构：

```typescript
// ① field 清单与分类（const 对象，分类由主包 codegen 确定）
export const Query = {
  paymentLog: { field: "paymentLog", type: "query" },
  paymentLogs: { field: "paymentLogs", type: "query" },
  // ...
} as const;

export const Mutation = {
  createPaymentLog: { field: "createPaymentLog", type: "mutation" },
  // ...
} as const;

export const operationSelection = {
  paymentLog: "createTime id ...",
  // ...
} as const;

// ② Service 接口（统一单 args 对象模式，返回 ChainablePromise）
export interface PaymentLogService {
  paymentLog(args?: PaymentLogArgs): ChainablePromise<PaymentLogConnection>;
  paymentLogs(args?: PaymentLogsArgs): ChainablePromise<PaymentLogConnection>;
  createPaymentLog(args?: CreatePaymentLogArgs | CreatePaymentLogInput): ChainablePromise<PaymentLog>;
}

// ③ Args 接口（含 where/order/first/after 分页参数）
export interface PaymentLogsArgs {
  first?: number;
  after?: string;
  where?: PaymentLogFilterInput;
  order?: Array<PaymentLogSortInput>;
}

export interface CreatePaymentLogArgs {
  input: CreatePaymentLogInput;
}

// ④ DTO interface（平铺，无继承）
export interface PaymentLog {
  id: number;
  uId: string;
  status: string;
  createTime: string;
  isDeleted: boolean;
}

// ⑤ 过滤类型（OperationFilterInput 家族）
export interface PaymentLogFilterInput {
  and?: PaymentLogFilterInput | null;
  or?: PaymentLogFilterInput | null;
  id?: LongOperationFilterInput | null;          // OperationFilterInput<number>
  uId?: StringOperationFilterInput | null;       // contains/startsWith/endsWith 族
  status?: EnumOperationFilterInput<string> | null;
  createTime?: DateTimeOperationFilterInput | null;
  isDeleted?: BooleanOperationFilterInput | null;
}

// ⑥ Connection 类型别名（双类型参数）
export type PaymentLogConnection = Connection<PaymentLog, PaymentLogEdge>;
export type PaymentLogEdge = Edge<PaymentLog>;
```

**解析规则**（正则轻量解析——括号深度扫描，因 TS7 已移除旧 compiler API 的 `createSourceFile`）：

| 规则 | 说明 |
|------|------|
| 手段 | 正则轻量解析（括号深度扫描；因 TS7 已移除旧 compiler API 的 `createSourceFile`）；先跳过 `import` 声明 |
| field 清单 | 直接读 `Query`/`Mutation` const 对象的键（含 type 分类），**不做启发式推断** |
| Service 方法 | 从 Service 接口方法签名提取：方法名、`args` 参数类型、返回类型 |
| 参数模式 | **统一单 `args` 对象**：`method(args?: XxxArgs)`。Codegen 时保持 `XxxArgs` 原始字段名（`where/order/first/after/input`） |
| 返回解包 | `ChainablePromise<T>` → `T`；`XxxConnection = Connection<Xxx, XxxEdge>` 别名 → 实体类型 `Xxx` |
| 实体提取 | `Connection<A, B>` 取第一类型参数 `A` |

### 3.2 生成产物 `ts-client.mock.g.ts` 结构（v2，对齐真实产物）

```typescript
// <auto-generated/> by @tkwf/tsclient-mock gen-mock-handlers
// 修改会丢失：编辑源文件后重新生成
import type { MockHandler, MockTransportOptions } from "@tkwf/tsclient-mock";
import { createMockDb, defineMock } from "@tkwf/tsclient-mock";
import type { Query, Mutation, PaymentLog, CreatePaymentLogInput } from "./ts-client.g";

// ── 内存数据库（骨架，Agent 填充初始数据） ──
export const db = createMockDb({ paymentLogs: [] });

// ── DTO → factory 配置（骨架，Agent 可按需调整） ──
export const paymentLogSchema = {
  _types: {
    id: { kind: "number", isId: true },
    uId: { kind: "string" },
    status: { kind: "enum", enumValues: [] },   // TODO: 枚举值需 Agent 填充（codegen 无 enum 声明）
    createTime: { kind: "date" },
    isDeleted: { kind: "boolean" },
  },
} as const;

// ── field handlers（骨架：db 操作已生成，Agent 只填业务意图） ──
export const handlers = {
  // paymentLogs (query): args.where/order/first/after → db.query
  paymentLogs: defineMock<{
    field: "paymentLogs";
    args: PaymentLogsArgs;
    result: PaymentLogConnection;
  }>((vars) => {
    const { where, order, first, after } = vars ?? {};
    return db.query("paymentLogs", where, order, { first, after });
  }),

  // paymentLog (query, 单条): db.queryOne
  paymentLog: defineMock<{
    field: "paymentLog";
    args: PaymentLogArgs;
    result: PaymentLog;
  }>((vars) => {
    return db.queryOne("paymentLogs", vars?.where);
  }),

  // createPaymentLog (mutation): db.insert
  createPaymentLog: defineMock<{
    field: "createPaymentLog";
    args: CreatePaymentLogArgs;
    result: PaymentLog;
  }>((vars) => {
    return db.insert("paymentLogs", vars?.input);
  }),

  // ... 每个 field 一个骨架
} satisfies Record<keyof typeof Query | keyof typeof Mutation, MockHandler>;

// ── 完整性覆盖检查：新增 field 缺 handler → 编译报错（Oracle 🟡#6） ──
type _AssertAllFieldsCovered =
  typeof handlers satisfies Record<keyof typeof Query | keyof typeof Mutation, unknown>;
```

**生成规则**（v2，对齐真实签名）：

| field 特征 | 生成骨架 |
|-----------|---------|
| `query` + 返回 `XxxConnection` | `db.query("xxx", args.where, args.order, { first, after })` |
| `query` + 返回单实体 | `db.queryOne("xxx", args.where)` |
| `mutation` + args 含 `input` | `db.insert("xxx", args.input)` |
| `mutation` + 命名 create/update/delete | `db.insert` / `db.update(table, id, patch)` / `db.remove(table, id)`（id 从 args 提取） |
| 无法归类 | `db.query("xxx")` + 注释"待 Agent 填充" |

> `last/before` 反向游标分页（Oracle 5.4）：生成骨架时若检测到 `last/before` 字段，加 TODO 注释标注"反向分页未实现，Agent 需自定义"。

### 3.3 DTO → MockFieldSchema 推导（v2）

| TS 类型 | MockFieldSchema |
|---------|----------------|
| `string` | `{ kind: "string" }` |
| `number` / `long` / `int` | `{ kind: "number" }` |
| `boolean` | `{ kind: "boolean" }` |
| `DateTime` / `string`（字段名含 `At`/`Time`） | `{ kind: "date" }` |
| 枚举字段（引用 `*EnumOperationFilterInput` 的实体字段） | `{ kind: "enum", enumValues: [] }` + `// TODO` 注释（Oracle 🟡#4：codegen 无 enum 值） |
| 嵌套 interface | `{ kind: "object", fields: {...} }` |
| `T[]` / `Array<T>` / `ListType` | `{ kind: "array", element: {...} }` |
| `id` 字段（严格匹配 `id`） | `isId: true`（沿用 v1.0.0 规则） |
| 循环引用 | schema 生成层面防无限递归（visited set，Oracle 测试缺口 #12） |
| 联合类型/未知 | `{ kind: "string" }` + 注释"待 Agent 确认" |

> 推导只做**保守映射**（保类型合法），真实感增强由 Agent/AI 填充层负责。

### 3.4 AI 编排基础设施

**不内置 LLM 调用**，提供三层基础设施（消费端 SKILL 组合使用）：

```typescript
// 1. 校验：mock 数据是否符合 DTO schema
export function validateMock<T>(data: unknown, schema: MockFieldSchema): { ok: boolean; errors: string[] };

// 2. 自愈：验证失败自动重试（generator 可注入，默认用 createMockFactory）
export function selfHealing<T>(options: {
  schema: MockFieldSchema;
  generator: () => unknown;     // LLM/工厂注入点
  maxRetries?: number;          // 默认 3
  validate?: (d: unknown) => { ok: boolean; errors: string[] };
}): Promise<T>;

// 3. 变更检测：codegen 产物内容 sha256 hash，sidecar 文件（<output>.hash）存储
export function detectChange(source: string): {
  hash: string;        // sha256 of source content
  changed: boolean;    // 与 sidecar 历史对比
};
```

**自愈重试逻辑**：

```
生成数据 → validateMock 校验
  ├─ 通过 → 返回
  └─ 失败 → 收集 errors → 重新生成（maxRetries 次）
       └─ 仍失败 → 抛错（含 errors 列表）
```

**detectChange**（Oracle 🟡#7）：输入为源文件内容字符串；sha256 计算后与 `<output>.hash` sidecar 文件比对，`changed=true` 时提示"codegen 产物已变更，请重新执行 gen-mock-handlers"。

### 3.5 defineMock 增强（v2，方案 B——不引入 ctx.type）

```typescript
// 泛型约束（codegen 产物使用）
export interface MockFieldContract<TField extends string, TArgs, TResult> {
  field: TField;
  args: TArgs;
  result: TResult;
}

export function defineMock<TContract extends MockFieldContract<string, unknown, unknown>>(
  handler: (
    vars: TContract["args"] | undefined,
    ctx: { sessionKey?: string; signal?: AbortSignal },  // 保持与 MockHandler 一致
  ) => TContract["result"] | Promise<TContract["result"]>,
): MockHandler;
```

- **运行时**：handler 签名与现 `MockHandler` 完全一致（`ctx` 无 `type`），无桥接问题（Oracle 🔴#5 方案 B）
- **编译期**：`field/args/result` 三元组约束——生成的 handler 传入 `vars?.where` 等的类型错误会在编译时暴露
- **兼容**：无泛型调用 `defineMock(handler)` 保持现状（TContract 默认 `unknown`）
