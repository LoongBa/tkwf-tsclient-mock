## 一、背景与目标

### 1.1 现状

v1.4.0（运行时契约校验）已可用。`mock-db.ts` 过滤引擎现状：
- **21 个操作符**：eq/neq、gt/gte/lt/lte、ngt/ngte/nlt/nlte、in/nin、contains/ncontains、startsWith/nstartsWith、endsWith/nendsWith、isTrue/isFalse、and/or
- **架构**：`FilterPredicate` 接口（7-28 行）+ `OPERATOR_EVALUATORS` 表（104-143 行）+ `matchRow` 两阶段递归引擎（154-189 行）+ `MAX_FILTER_DEPTH = 5`
- 测试覆盖完备（自有格式 + OperationFilterInput 家族两种格式均独立测试）

**缺口**：
1. **空值检测**：无 `isNull`/`isNotNull` 操作符——无法过滤 null/undefined 字段
2. **范围过滤**：无 `between`——闭区间 [low, high] 需组合 gte+lte，无单操作符
3. **大小写不敏感**：contains/startsWith/endsWith 均区分大小写，无 `mode: insensitive` 切换
4. **数组字段**：无 `containsAny`/`containsAll`——数组字段过滤语义缺失
5. **类型对齐**：上游 `BooleanOperationFilterInput` 缺 isTrue/isFalse；`DateTimeOperationFilterInput` 缺 ngt/ngte/nlt/nlte（运行时已支持，类型未对齐）

### 1.2 目标

1. **新增操作符**：`isNull`/`isNotNull`、`between`、`mode`（QueryMode 枚举）、`containsAny`/`containsAll`
2. **null 语义规范**：字段为 null 时仅 `isNull` 操作符生效，其他操作符返回 false（对齐 Hasura/Prisma 共识）
3. **大小写策略**：`mode: QueryMode`（default/insensitive），Prisma/Keystone 主流方案——单字段设置影响该字段所有字符串模式匹配
4. **类型对齐**：补齐上游 OperationFilterInput 家族类型差异（只加类型字段，不改运行时）
5. **向后兼容**：现有 21 操作符行为不变，新增全为可选字段

### 1.3 不做什么

- ❌ 不做关联过滤嵌套（`items: { some: { price: { gt: 100 } } }`）——需要实体关联图改造，超出本版范围
- ❌ 不做 `regex` 操作符（高级字符串过滤，低优先）
- ❌ 不做 `hasKey`/`hasEvery`/`hasSome`（JSON 字段低优先）
- ❌ 不做 `isNotNull` 语法糖（`isNull: false` 已覆盖非 null 语义，isNotNull 留待后续版本——Oracle 🟡4）
- ❌ 不改 `matchRow` 引擎架构（新增操作符只加 `OPERATOR_EVALUATORS` 表 + `FilterPredicate` 字段）
- ❌ 不改主包 `@tkwf/tsclient`（类型对齐仅指 mock 侧类型定义）

## 三、方案设计

### 3.0 设计决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 空值检测 | **`isNull?: boolean`**（字段为 null 时仅此操作符生效） |
| 2 | 范围过滤 | **`between?: readonly [low, high]`** 闭区间（含边界） |
| 3 | 大小写 | **`mode?: QueryMode`** 枚举（default/insensitive），Prisma 方案 |
| 4 | 数组字段 | **`containsAny?: readonly unknown[]` / `containsAll?: readonly unknown[]`** |
| 5 | `isNull` 互斥 | isNull 提供时**忽略其他操作符**（惰性，不抛错） |
| 6 | between 类型 | **数字/日期**均可（`[low, high]` 用 compareValues 比较） |

> **v2 修订（2026-08-12，并入 Oracle 审查意见）**：3 个 🔴 阻塞项全部解决（containsAny/containsAll 改用 compareValues / mode 实现路径明确为 matchRow 归一化 / isNull 门控与求值器职责划分），4 个 🟡 建议全部采纳（互斥语义边界明确 / between 防御性校验 / 类型对齐改名类型文档对齐 / isNotNull 标注未来版本）。详见 §四 之后补充的修订说明。

### 3.1 QueryMode 类型

```typescript
/** 字符串模式匹配大小写模式（Prisma 风格） */
export type QueryMode = "default" | "insensitive";
```

- `default`：区分大小写（现有行为）
- `insensitive`：不区分大小写（比较前 `.toLowerCase()`）

### 3.2 FilterPredicate 扩展

```typescript
export interface FilterPredicate {
  // ... 现有 21 个操作符不变 ...

  // 新增（v1.5.0）
  isNull?: boolean;                       // 空值检测：字段为 null/undefined 时匹配
  between?: readonly [unknown, unknown];  // 闭区间 [low, high]：low <= value <= high
  mode?: QueryMode;                       // 字符串模式匹配大小写（仅影响 contains/startsWith/endsWith）
  containsAny?: readonly unknown[];       // 数组字段：包含任一值
  containsAll?: readonly unknown[];       // 数组字段：包含全部值
}
```

**containsAny/containsAll 比较策略（Oracle 审查 🔴1）**：必须使用 `compareValues`（与全引擎 `in`/`nin` 一致），**不能用 `Array.includes()`**（严格相等 `===` 无法处理 Date 对象引用比较和跨类型回退）：

```typescript
containsAny: (rv, op) => {
  if (!Array.isArray(rv)) return false;
  return (op as readonly unknown[]).some((v) =>
    rv.some((rvItem) => compareValues(rvItem, v) === 0),
  );
},
containsAll: (rv, op) => {
  if (!Array.isArray(rv)) return false;
  return (op as readonly unknown[]).every((v) =>
    rv.some((rvItem) => compareValues(rvItem, v) === 0),
  );
},
```

### 3.3 OPERATOR_EVALUATORS 扩展

```typescript
const OPERATOR_EVALUATORS: Record<OperatorName, (rv: unknown, op: unknown) => boolean> = {
  // ... 现有实现不变 ...

  // 新增（v1.5.0）
  isNull: (rv, op) => {
    if (op !== true) return true;  // 惰性：非 true 时放行（对齐 isTrue/isFalse 模式）
    return rv === null || rv === undefined;
  },
  between: (rv, op) => {
    if (!Array.isArray(op) || op.length < 2) return false;  // 防御性校验（Oracle 🟡2）
    const [low, high] = op as readonly [unknown, unknown];
    return compareValues(rv, low) >= 0 && compareValues(rv, high) <= 0;
  },
  containsAny: /* 见上方 🔴1 修正：用 compareValues */,
  containsAll: /* 见上方 🔴1 修正：用 compareValues */,
};
```

**`mode` 实现路径（Oracle 审查 🔴2，推荐 matchRow 归一化）**：`mode` 是修饰符，不是独立操作符。实现方式：`matchRow` 阶段 1 在调用 `evaluate` 前归一化 `rv`/`operand`，仅对 6 个字符串模式操作符生效：

```typescript
// matchRow 阶段 1 内，for (const [op, operand] of ...) 循环中：
const STRING_OPS = new Set(["contains", "ncontains", "startsWith", "nstartsWith", "endsWith", "nendsWith"]);
const mode = (predicate as Record<string, unknown>)["mode"] as QueryMode | undefined;

let effectiveRv = rowValue;
let effectiveOperand = operand;
if (mode === "insensitive" && STRING_OPS.has(op)) {
  effectiveRv = String(rowValue).toLowerCase();
  effectiveOperand = String(operand).toLowerCase();
}

if (!evaluate(effectiveRv, effectiveOperand)) return false;
```

**优点**：求值器保持纯函数 `(rv, op) => boolean` 签名不变，`mode` 只影响白名单 6 个操作符（n 前缀变体同样受 mode 影响——`ncontains` + insensitive = "不包含（大小写不敏感）"）。

**null 门控与 isNull 求值器分工（Oracle 审查 🔴3）**：

| 层 | 职责 | 触发条件 |
|----|------|---------|
| **null 门控**（matchRow 级，操作符循环前） | 字段 null/undefined 时仅 isNull 生效 | `rv === null \|\| rv === undefined` |
| **isNull 求值器**（OPERATOR_EVALUATORS 级） | 非 null 字段上 `isNull: true` 正确返回 false | 字段非 null 且 predicate 含 isNull |

**注意**：null 门控必须是操作符循环的**前置守卫**——若只有求值器而无门控，`isNull: false` 对 null 字段会惰性放行（返回 true），与"null 字段仅 isNull 生效"的语义矛盾。二者互补，缺一不可。

**null 语义（对齐社区共识）**：
```typescript
// matchRow 阶段 1 内：字段为 null/undefined 时（前置守卫）
if (rv === null || rv === undefined) {
  const isNullOp = (predicate as Record<string, unknown>)["isNull"];
  if (isNullOp !== undefined) return isNullOp === true;
  return false;  // 其他所有操作符对 null 返回 false
}
```

**`isNull` 互斥语义边界（Oracle 审查 🟡1）**：
> 当**字段值为 null/undefined** 时，`isNull` 操作符生效并忽略同字段的其他操作符（null 门控 return 实现）。当**字段值非 null** 时，`isNull` 作为普通操作符参与 AND 求值，与 `isTrue`/`isFalse` 模式一致：`isNull: true` 对非 null 字段返回 false，`isNull: false` 放行。

### 3.4 OperatorName 联合类型扩展

```typescript
type OperatorName = "eq" | "neq" | "gt" | "gte" | "lt" | "lte"
  | "ngt" | "ngte" | "nlt" | "nlte"
  | "in" | "nin"
  | "contains" | "ncontains" | "startsWith" | "nstartsWith" | "endsWith" | "nendsWith"
  | "isTrue" | "isFalse"
  // v1.5.0 新增
  | "isNull" | "between" | "containsAny" | "containsAll";
```

**`mode` 不进 OperatorName**（它是修饰符，不是独立操作符）。

### 3.5 类型文档对齐（Oracle 审查 🟡3：原"类型对齐"改名）

**范围澄清**：`FilterPredicate` 运行时已覆盖全部 OperationFilterInput 操作符（26 个）。`sample.g.ts` 是**测试夹具**，修改它不影响消费者——本项仅为**文档对齐**：更新夹具类型使其反映完整的 OperationFilterInput 家族定义，为未来 codegen 输出提供参考模板。**不修改上游**。

| 家族类型 | 现缺 | 补齐 |
