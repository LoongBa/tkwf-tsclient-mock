## 一、背景与目标

### 1.1 现状

v1.5.0（查询语义增强）已添加 isNull/between/mode/containsAny/containsAll。过滤引擎现状：
- **26 个操作符**：现有标量/字符串/布尔/数组操作符
- `matchRow` 两阶段引擎：阶段 1 叶子谓词 + 阶段 2 and/or 子树
- `runQuery` 四阶段管道：读表 → 过滤 → 排序 → 分页
- `registerQuery`/`registerMutation`：`fieldTableMap.set()`，但该 Map **从未被 query 引擎读取**（死代码）

**缺口**：
1. **无关系注册**：mock-db 不知道表之间存在外键关联
2. **无关联过滤**：`items: { some: { price: { gt: 100 } } }` 在 matchRow 中静默跳过（未识别的键被 continue）
3. **无 some/every/none 操作符**：FilterPredicate/FilterInput 无关联过滤语义
4. **无关联查询**：`runQuery` 只查单表，不做跨表关联解析

### 1.2 目标

1. **关系注册 API**：`MockDb.registerRelation(table, field, { type, targetTable, foreignKey })`——声明外键映射
2. **some/every/none 操作符**：matchRow 识别关联字段谓词，递归到关联表执行子查询
3. **惰性关联解析**：MirageJS 式外键查找（`Map.get()`），非 JOIN
4. **空关联边界**：some→false、every→true（空真）、none→true（空真）——对齐 Prisma 语义
5. **to-one 关系支持**：`belongsTo` 类型，单个外键（标量），谓词直接应用于关联行
6. **向后兼容**：未注册关系的字段过滤行为不变（静默跳过）

### 1.3 不做什么

- ❌ 不做自动关系推导（codegen 解析 DTO 类型推断关联——后续版本）
- ❌ 不做双向同步（MirageJS 式 `inverse` 自动维护外键一致性——后续版本）
- ❌ 不做 `is: null`/`isNot: null` 空关联查询（Prisma 语义，后续版本——Oracle S3）
- ❌ 不做聚合过滤（Hasura 式 `count`/`avg`/`bool_and`——后续版本）
- ❌ 不改 `runQuery` 管道架构（关联解析仅嵌入 matchRow，不改变 query 入口）
- ❌ 不改 `registerQuery`/`registerMutation`（现有 fieldTableMap 死代码保持不动）

## 三、方案设计

### 3.0 设计决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 关系类型 | **`"hasMany"` + `"belongsTo"`**（MirageJS 命名） |
| 2 | 操作符命名 | **`some`/`every`/`none`**（Prisma 命名） |
| 3 | 关联解析 | **惰性外键查找**（MirageJS 式，Map.get O(1)） |
| 4 | 空关联边界 | **some→false / every→true / none→true**（Prisma 语义） |
| 5 | 深度限制 | **沿用 `MAX_FILTER_DEPTH = 5`**（关联嵌套计入 depth） |
| 6 | 关系注册位置 | **`MockDb` 接口方法**（`registerRelation`） |

> **v2 修订（2026-08-12，并入 Oracle 审查意见）**：2 个 🔴 阻塞项全部解决（B1: matchRow 移入闭包直接访问 tables / B2: belongsTo 用 some 包装谓词），9 个 🟡 建议全部采纳（类型导出/谓词形状/Prisma 偏差/目标表缺失/非数组 FK/数据集交互/FK 类型/非空断言/测试补充）。详见 §四 后的修订说明。

### 3.1 关系注册 API

```typescript
/** 关系类型 */
export type RelationType = "hasMany" | "belongsTo";

/** 关系定义 */
export interface RelationDef {
  type: RelationType;
  targetTable: string;     // 关联表名
  foreignKey: string;       // 外键字段名（当前表中的字段名）
}

// MockDb 接口新增方法
export interface MockDb {
  // ... 现有方法不变 ...

  /**
   * 注册实体关系。
   *
   * @param table 当前表名
   * @param field 关联字段名（filter 中使用的键名）
   * @param relation 关系定义
   *
   * @example
   * db.registerRelation("paymentLogs", "merchant", {
   *   type: "belongsTo",
   *   targetTable: "merchants",
   *   foreignKey: "merchantId",
   * });
   * db.registerRelation("merchants", "logs", {
   *   type: "hasMany",
   *   targetTable: "paymentLogs",
   *   foreignKey: "merchantId",
   * });
   */
  registerRelation(table: string, field: string, relation: RelationDef): void;
}
```

**外键约定**：
- `hasMany`：当前表的外键字段值类型为 `(string|number)[]`（ID 数组），如 `itemIds: [1, 2, 3]`
- `belongsTo`：当前表的外键字段值类型为 `string|number`（单 ID），如 `merchantId: 5`

### 3.2 some/every/none 操作符

**FilterInput 隐式支持**（不新增独立类型，`some`/`every`/`none` 作为字段谓词的值中的键名）：

```typescript
// 使用方式（消费端）：
// 查询：至少有一条关联记录 amount > 100
db.query("paymentLogs", {
  items: { some: { amount: { gt: 100 } } },
});

// 查询：所有关联记录 status 都是 SUCCESS
db.query("paymentLogs", {
  items: { every: { status: { eq: "SUCCESS" } } },
});

// 查询：没有关联记录 status 是 FAILED
db.query("paymentLogs", {
  items: { none: { status: { eq: "FAILED" } } },
});

// belongsTo：单关联行，用 some 包装（Oracle 审查 🔴 B2：belongsTo 必须用 some，不能直接谓词）
db.query("paymentLogs", {
  merchant: { some: { name: { contains: "Loong" } } },  // 等同 Prisma is
});
```

**`belongsTo` 不需要独立的 `is` 操作符**——单个关联行直接应用谓词即可（与 `and`/`or` 子树同样的递归模式）。

### 3.3 RelationRegistry 内部存储

```typescript
// createMockDb 闭包内
const relationRegistry = new Map<string, Map<string, RelationDef>>();
// 外层 key：当前表名，内层 key：关联字段名

// registerRelation 实现
registerRelation(table: string, field: string, relation: RelationDef): void {
  let tableRelations = relationRegistry.get(table);
  if (!tableRelations) {
    tableRelations = new Map();
    relationRegistry.set(table, tableRelations);
  }
  tableRelations.set(field, relation);
}
```

### 3.4 matchRow 关联解析（阶段 2 新增）

当前 matchRow 结构：
```
阶段 1: 叶子谓词（遍历 filterKeys，跳过 and/or）
阶段 2: and/or 子树评估
```

v1.6.0 新增**阶段 1.5**（在叶子谓词循环中，当遇到关联字段时）：

```typescript
// matchRow 阶段 1 内，for (const key of filterKeys) 循环中：
if (key === "and" || key === "or") continue;
const predicate = filter[key];
if (!predicate || typeof predicate !== "object" || Array.isArray(predicate)) continue;

// 检查是否为关联过滤操作符
const predObj = predicate as Record<string, unknown>;
if ("some" in predObj || "every" in predObj || "none" in predObj) {
  // 关联过滤（阶段 1.5）
  if (!evaluateRelationFilter(row, key, predObj, table, depth, context)) return false;
  continue;
}

// 现有叶子谓词逻辑（null 门控 → mode → 操作符评估）...
```

**`evaluateRelationFilter` 逻辑**（闭包内，可访问 `tables` 和 `relationRegistry`）：

```typescript
function evaluateRelationFilter(
  row: Record<string, unknown>,
  field: string,       // 关联字段名（如 "items"）
  predicate: Record<string, unknown>,  // { some: { amount: { gt: 100 } } }
  table: string,       // 当前表名
  depth: number,
): boolean {
  const tableRelations = relationRegistry.get(table);
  const relation = tableRelations?.get(field);
  if (!relation) return true;  // 未注册关系 → 跳过（不阻塞）

  // 解析关联行
  const fkValue = row[relation.foreignKey];
  let relatedRows: Record<string, unknown>[];

  if (relation.type === "hasMany") {
    const fkArray = Array.isArray(fkValue) ? (fkValue as (string | number)[]) : [];
    const targetTable = tables.get(relation.targetTable);
    if (!targetTable) return false;
    relatedRows = fkArray
      .map((id) => targetTable.get(id))
      .filter((r): r is Record<string, unknown> => r !== undefined);
  } else {
    // belongsTo：foreignKey 是单 ID
    // 注意：belongsTo 必须用 some 包装谓词（Oracle 审查 🔴 B2）
    const fkId = fkValue as string | number | undefined;
    if (fkId === undefined || fkId === null) {
      relatedRows = [];
    } else {
      const targetTable = tables.get(relation.targetTable);
      relatedRows = targetTable?.get(fkId) ? [targetTable.get(fkId)!] : [];
    }
  }

  // 确定操作符
  let op: "some" | "every" | "none" | undefined;
  let subFilter: Record<string, unknown> | undefined;
  if ("some" in predicate) { op = "some"; subFilter = predicate.some as Record<string, unknown>; }
  else if ("every" in predicate) { op = "every"; subFilter = predicate.every as Record<string, unknown>; }
  else if ("none" in predicate) { op = "none"; subFilter = predicate.none as Record<string, unknown>; }

  if (!op || !subFilter) return true;  // 未知操作符 → 跳过

  // 空关联边界（对齐 Prisma 语义）
  if (relatedRows.length === 0) {
    switch (op) {
      case "some":  return false;  // 空 → 无元素匹配
      case "every": return true;   // 空真（vacuous truth）
      case "none":  return true;   // 空 → 无元素违反
    }
  }

  // 对关联行递归 matchRow（闭包内直接调用，无需传 context）
  switch (op) {
    case "some":
      return relatedRows.some((r) => matchRow(r, subFilter, depth + 1));
    case "every":
      return relatedRows.every((r) => matchRow(r, subFilter, depth + 1));
    case "none":
      return !relatedRows.some((r) => matchRow(r, subFilter, depth + 1));
  }
}
```

**深度限制**：关联递归计入 `depth`，每次关联过滤调用 `matchRow` 时 depth+1。`MAX_FILTER_DEPTH = 5` 保持不变，关联嵌套 5 层后抛错。

**`matchRow` 签名变更**：`matchRow` 移入 `createMockDb` 闭包内，直接闭包访问 `tables` 和 `relationRegistry`（Oracle 审查 🔴 B1）。不再需要独立 `context` 参数——`and/or` 递归和关联递归均通过闭包访问注册表。

### 3.5 向后兼容

- 未注册关系的字段：`predicate 中有 `some`/`every`/`none` 但 `relationRegistry` 中无对应关系 → `return true`（跳过，不阻塞任何行）——与 v1.5.0 行为一致（未知键静默跳过）
- 未注册关系 + 字段值非关联对象（如普通标量）：现有叶子谓词逻辑处理，无变化
- `registerRelation` 是纯新增方法，不影响现有 `MockDb` 接口的消费代码
