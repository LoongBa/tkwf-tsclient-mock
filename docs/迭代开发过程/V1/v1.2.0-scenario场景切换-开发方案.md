## 一、背景与目标

### 1.1 现状

v1.1.0（codegen + AI 编排）已可用：
- `MockTransport`：field 分发 + `fieldOptions`（delayMs/error/failRate/timeoutMs）注入
- `createMockDb`：单数据集内存数据库（构造时一份 `_entities` + 一份快照）
- `gen-mock-handlers`：生成全部 field 的 handler 骨架 + `createMockDb` + DTO schema
- `validateMock` / `selfHealing` / `detectChange`：AI 编排基础设施（与场景正交）

**缺口**：
1. mock 数据是**固定一套**——演示"空态/错误态/加载态"需要改代码或手改数据，无法运行时切换
2. Storybook 等 UI 开发场景需要**按场景渲染**（默认态看正常数据、空态看空列表、错误态看报错 UI、加载态看 loading），当前无此能力
3. 原型（宽松 mock）→ 开发（真实调试）→ 测试（确定性 mock）的分阶段切换无统一机制

### 1.2 目标

1. **场景切换**：`MockTransport.setScenario(name)` + `ctx.scenario` 扩展——运行时切换 mock 行为
2. **四种场景**：默认态（正常数据）/ 空态（空数据）/ 错误态（注入 error/failRate）/ 加载态（长 delay）
3. **多数据集**：`createMockDb` 支持命名数据集字典（`datasets: { default, empty, ... }`），切换即换数据
4. **场景协调**：`createScenarioContext` 封装"db 数据 + transport 注入"的场景联动切换
5. **codegen 场景骨架**：`gen-mock-handlers` 生成 `scenarios`/`scenarioOverrides` 骨架，数据留消费端 Agent 填充（延续"骨架 + Agent 填充"模式）
6. **分阶段策略**：作为 README 文档指南说明（原型→开发→测试如何用场景组合实现）

### 1.3 不做什么

- ❌ 不内置 Storybook 插件/装饰器（提供接口，消费端自行接线）
- ❌ 不做 HTTP 层 mock server
- ❌ 不内置分阶段模式代码（`stagedMode` 枚举），仅文档指南
- ❌ 不改 `validateMock`/`selfHealing`/`detectChange` 签名（场景与 AI 编排正交）
- ❌ 不改主包 `@tkwf/tsclient`（Transport 接口保持原样，场景扩展仅限 mock 层）

### 3.1 场景模型

```typescript
/** 内置约定场景名（消费端可自定义扩展） */
export type BuiltinScenario = "default" | "empty" | "error" | "loading";

/** 场景级 transport 配置（与 MockTransportOptions 对齐） */
export interface ScenarioConfig {
  delayMs?: number;                                   // 加载态：长延迟
  error?: unknown;                                    // 场景级快捷注入：整个场景所有 field 统一报错（fieldOptions 可逐 field 覆盖，🟡B2）
  fieldOptions?: Record<string, FieldOption>;        // 错误态：error / failRate / timeoutMs
}
```

**场景名约定**：
- `default`：正常数据 + 无注入（默认值）
- `empty`：空数据（db 数据集切换）+ 无注入
- `error`：正常数据 + `fieldOptions` 注入 error/failRate（错误态）
- `loading`：正常数据 + 长 delayMs（加载态）

**场景 = 数据视图（db）+ 注入配置（transport）**，两者以场景名为 key 关联。

### 3.2 mock-db 多数据集（`src/mock-db.ts` 扩展）

```typescript
export type DatasetSeed = Record<string, Record<string, unknown>[]>;

export interface MockDbOptions {
  seed?: number;
  datasets?: Record<string, DatasetSeed>;  // 命名数据集字典（可选）
}

// createMockDb(entities, { datasets }) —— 向后兼容：不传 datasets 时行为不变
export function createMockDb(
  entities: DatasetSeed,
  options?: MockDbOptions,
): MockDb;

// MockDb 接口新增
export interface MockDb {
  // ... 现有方法不变
  switchDataset(name: string): void;       // 切换当前数据集（不存在则 throw）
  getDatasetName(): string;                // 当前数据集名（默认 "default"）
  listDatasets(): string[];                // 全部数据集名（含 "default"）——供协调器/Storybook 枚举（🟡B1）
  reset(name?: string): void;              // 无参：重置"当前活跃数据集"到其初始快照；传 name：切换到该数据集并重置
}
```

**实现要点**：
- 构造时：`datasets` 字典 → 每份数据集独立建表 + 快照；`_entities` 视为 `default` 数据集
- `switchDataset(name)`：用目标数据集的快照重建 `tables`（保留 field→table 注册映射）
- `reset(name?)` 语义（Oracle 审查 🔴#4 明确）：**无参 = 重置当前活跃数据集到其初始快照**（`switchDataset("empty")` 后 `reset()` 回到 empty 初始快照，而非 default）；**有参 = 切换到该数据集并重置**（等价 `switchDataset(name)` + `reset()`）
- **兼容性**：不传 `datasets` 时，`listDatasets()` 返回 `["default"]`，`switchDataset("default")` 合法、其他名字抛错；`reset()` 行为与 v1.1.0 完全一致

### 3.3 transport 层场景注入（`src/mock-transport.ts` 扩展）

```typescript
export interface MockTransportOptions {
  delayMs?: number;
  fieldOptions?: Record<string, FieldOption>;
  scenario?: string;                              // 初始场景名（默认 "default"）
  scenarios?: Record<string, ScenarioConfig>;     // 场景配置字典
}

export class MockTransport implements Transport {
  setScenario(name: string): void;      // 切换场景（不存在则 throw）
  getScenario(): string;
  getScenarioNames(): string[];         // 全部场景名（含 "default"）——供协调器/Storybook 枚举（🟡B1）
  // execute() 时：
  //   ctx = { sessionKey, signal, scenario: this.scenario }
  //   注入解析优先级（场景优先，逐项覆盖）：
  //     error:     scenarios[scenario].fieldOptions?.[field]?.error ?? scenarios[scenario].error ?? fieldOptions?.[field]?.error
  //     failRate:  scenarios[scenario].fieldOptions?.[field]?.failRate ?? fieldOptions?.[field]?.failRate
  //     delayMs:   scenarios[scenario].fieldOptions?.[field]?.delayMs ?? scenarios[scenario].delayMs ?? fieldOptions?.[field]?.delayMs ?? delayMs
  //     timeoutMs: scenarios[scenario].fieldOptions?.[field]?.timeoutMs ?? fieldOptions?.[field]?.timeoutMs
}
```

**执行管道变化**（现有流程保持不变，仅注入值按场景解析）：

```
Step 1: 解析场景注入
  effFieldOptions = merge(scenarios?.[scenario]?.fieldOptions, fieldOptions)   // 场景优先，逐 field 深度合并
  effDelayMs      = scenarios?.[scenario]?.delayMs ?? delayMs
  effError        = scenarios?.[scenario]?.error   // 场景级快捷注入（fieldOptions 未命中时兜底）
Step 2-6: 现有 error → failRate → delay → handler → timeout 流程不变
Step 4: handler(vars, { sessionKey, signal, scenario })
```

**`ctx.scenario` 扩展**：
- `MockHandler` 签名 `(vars, ctx: { sessionKey?, signal?, scenario? })` —— **场景名可选**，向后兼容
- `defineMock` 泛型签名同步更新（handler 的 ctx 参数类型）
- 行为不变：handler 内部不读 `ctx.scenario` 时，场景切换仅影响注入，不影响 handler 逻辑

### 3.4 场景协调器（`src/scenario.ts` 新文件）

```typescript
export interface ScenarioContext {
  setScenario(name: string): void;     // 同时切换 db 数据集 + transport 场景
  getScenario(): string;
  readonly db: MockDb;
  readonly transport: MockTransport;
}

export function createScenarioContext(options: {
  db: MockDb;
  transport: MockTransport;
  // 注意：不再接受 datasets —— 数据集由 createMockDb 独占持有，
  // 协调器通过 db.listDatasets() 读取，避免双数据源（Oracle 审查 🔴#2）
  scenarios?: Record<string, ScenarioConfig>;  // 场景配置（传入则注册到 transport）
}): ScenarioContext;
```

**协调逻辑**（`setScenario(name)`，校验优先 + 失败回滚，Oracle 审查 🔴#3）：
1. **预校验**：`name` 必须存在于 `db.listDatasets()` 或 `transport.getScenarioNames()` 至少一侧；两侧都无 → throw，不执行任何切换
2. 若 `db.listDatasets()` 含该名 → `db.switchDataset(name)`
3. 若 `transport.getScenarioNames()` 含该名 → `transport.setScenario(name)`
4. 任一侧切换抛错 → 将已完成切换的一侧**回滚**到切换前场景，保证原子性
5. 场景可同时有数据 + 注入（如 `emptyLoading` 自定义场景）

**典型用法**（消费端）：

```typescript
import { createMockDb, MockTransport, createScenarioContext } from "@tkwf/tsclient-mock";

const db = createMockDb({ paymentLogs: [] }, {
  datasets: {
    default: { paymentLogs: [{ id: 1, status: "ok" }] },
    empty: { paymentLogs: [] },
  },
});
const transport = new MockTransport({ ...handlers }, {
  scenarios: {
    error: { fieldOptions: { paymentLogs: { error: new Error("boom") } } },
    loading: { delayMs: 3000 },
  },
});
// 数据集已注册到 db（createMockDb 独占持有），协调器从 db.listDatasets() 读取
const scenario = createScenarioContext({ db, transport, scenarios: {...} });

scenario.setScenario("empty");    // 空态
scenario.setScenario("error");    // 错误态
scenario.setScenario("loading");  // 加载态
```

### 3.5 codegen 场景骨架（`src/codegen/` 扩展）

生成产物在 v1.1.0 基础上新增两段：

```typescript
// ── 场景数据集骨架（数据留 Agent 填充） ──
export const scenarios = {
  default: {
    paymentLogs: [] satisfies PaymentLog[],
    merchants: [] satisfies Merchant[],
  },
  empty: {
    paymentLogs: [] satisfies PaymentLog[],
    merchants: [] satisfies Merchant[],
  },
};

// ── 场景注入配置骨架 ──
export const scenarioOverrides: Record<string, ScenarioConfig> = {
  error: { fieldOptions: { /* TODO: Agent 按 field 填 error / failRate */ } },
  loading: { delayMs: 3000 },
};
```

**改动**：
- `templates.ts`：新增 `scenariosSkeleton()` / `scenarioOverridesSkeleton()`（复用现有表名清单）
- `generate.ts`：产物头部在 `db` 块后追加场景骨架
- **向后兼容**：不生成新导入依赖（`ScenarioConfig` 类型从包导入，`templates.ts` 的 `imports()` 追加到 type imports），CLI 参数不变
- **`satisfies` 降级**（Oracle 审查 🟡B4）：`scenariosSkeleton()` 对无实体类型（DTO-only）的表不输出 `satisfies` 约束，仅输出 `[]` + 注释
