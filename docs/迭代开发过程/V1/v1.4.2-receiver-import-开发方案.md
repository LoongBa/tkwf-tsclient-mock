## 二、技术设计

### 2.1 buildDataset 未知表检测（代码增强）

**当前实现**（`mock-db.ts:796-810`）：

```typescript
buildDataset(dataset: DatasetSeed, options?: { strict?: boolean }): void {
  for (const [table, rows] of Object.entries(dataset)) {
    const tableMap = tables.get(table) ?? new Map();  // 未知表静默创建
    for (const row of rows) {
      const id = (row.id ?? row.Id) as string | number;
      tableMap.set(id, { ...row });
    }
    tables.set(table, tableMap);
  }
  if (options?.strict) {
    validateDatasetFK();
  }
}
```

**问题**：`createMockDb({ paymentLogs: [] })` 声明了表名 `paymentLogs`。若 seed 用 `PaymentLog`（大写），buildDataset 创建 `PaymentLog` 表填入数据，但 handler 查询 `paymentLogs`——数据静默丢失。

**增强方案**：

```typescript
buildDataset(dataset: DatasetSeed, options?: { 
  strict?: boolean;
  unknownTables?: "warn" | "error" | "ignore";  // v1.4.2 新增，默认 "ignore"
}): void {
  const mode = options?.unknownTables ?? "ignore";
  const declaredTables = new Set(tables.keys());  // createMockDb 初始声明的表名
  
  if (mode !== "ignore" && declaredTables.size > 0) {
    const unknown = Object.keys(dataset).filter(t => !declaredTables.has(t));
    if (unknown.length > 0) {
      const msg = `[tsclient-mock] buildDataset: seed 包含未声明的表 [${unknown.join(", ")}]，已声明的表为 [${[...declaredTables].join(", ")}]。表名不匹配会导致数据注入到无人查询的表，页面空白。`;
      if (mode === "error") throw new Error(msg);
      console.warn(msg);
    }
  }
  
  // 原有逻辑不变
  for (const [table, rows] of Object.entries(dataset)) {
    const tableMap = tables.get(table) ?? new Map();
    for (const row of rows) {
      const id = (row.id ?? row.Id) as string | number;
      tableMap.set(id, { ...row });
    }
    tables.set(table, tableMap);
  }
  if (options?.strict) {
    validateDatasetFK();
  }
}
```

**设计要点**：
- `declaredTables.size > 0` 守卫：`createMockDb({})` 空初始化时不检测（无法区分"故意空初始化"与"表名不匹配"），仅当声明了至少一张表时才检测
- 默认 `"ignore"`：完全向后兼容，不影响现有调用
- 推荐接收方使用 `"warn"`：开发期可见警告，不阻断流程
- `"error"`：CI/严格场景，立即暴露表名不匹配

### 2.2 SKILL.md 接收方导入工作流

在现有 Step 4（跨语言产出）之后新增 **Step 5：接收方导入**（当从别的项目接收 mock 文件时）。

#### Step 5a：接收 DatasetSeed JSON（直接数据——推荐用于测试）

**适用**：对方只做测试，不关心生成逻辑，需要确定性数据。

**接收文件**：
- `seed.json`（DatasetSeed JSON，由 `serializeDatasetSeed` 或 `exportDatasetSeed` 产出）
- `MOCK_SPEC.md`（可选，人类可读的数据策略说明）

**导入步骤**：

```typescript
// Node 环境
import { importDatasetSeed } from "@tkwf/tsclient-mock/server";
importDatasetSeed(db, "path/to/seed.json");

// 或浏览器环境（从内嵌 TS 模块加载）
import { parseDatasetSeed } from "@tkwf/tsclient-mock";
const seed = parseDatasetSeed(jsonString);
db.buildDataset(seed, { unknownTables: "warn" });  // v1.4.2：检测表名不匹配
```

**注意**：
- `db` 必须由本项目的 `createMockDb({...})` 初始化，表名与 `ts-client.mock.g.ts` 的 handler 查询表名一致
- `unknownTables: "warn"` 可在开发期暴露表名不匹配（v1.4.2 新增）
- MOCK_SPEC.md §1（API 映射表）是项目特定的，不能直接复用——需用本项目 `ts-client.g.ts` 重跑 `gen-mock-handlers --mock-spec`

#### Step 5b：接收 MockDataSpec JSON（规则——需重新生成）

**适用**：对方要调整条数/场景/分布，或做跨语言重新生成。

**接收文件**：
- `mock-data-spec.json`（MockDataSpec JSON，结构化规则）
- `MOCK_SPEC.md`（人类可读策略，§2-3 可移植）

**导入步骤**：

```typescript
import { parseMockDataSpec, generateFromSpec } from "@tkwf/tsclient-mock";
import { loadMockDataSpec } from "@tkwf/tsclient-mock/server";  // Node 文件读取

// Node: const spec = loadMockDataSpec("path/to/mock-data-spec.json");
// 浏览器: const spec = parseMockDataSpec(jsonString);
const spec = parseMockDataSpec(jsonString);
const seed = generateFromSpec(spec, { faker: fakerZH_CN, scenario: "default" });
db.buildDataset(seed, { unknownTables: "warn" });
```

**注意**：
- 同一 spec + 同一 seed → 确定性数据完全一致（跨项目/跨语言）
- `generateFromSpec` 需要 faker 实例（如使用 `faker` 策略）
- 场景参数 `scenario` 可选（v1.4.1 新增）

#### Step 5c：接收 MOCK_SPEC.md（仅策略文档）

**适用**：对方从零开始，只需数据策略参考。

**操作**：
1. 复制 MOCK_SPEC.md 到 `<项目>/.TKWF/merchant/MOCK_SPEC.md`（或 `src/mock/MOCK_SPEC.md`）
2. **删除 §1 映射表**（`<!-- auto-generated -->` 标记段）——本项目 API 不同，需重新生成
3. 运行 `gen-mock-handlers --mock-spec <路径>` 重新生成 §1
4. 按 §2 数据策略 + §3 表间关系编写本项目的 `MockDataSpec JSON`
5. 后续走 Step 2-3（填写规则 → 生成验证）

### 2.3 G07D 场景指南新增 §4.7-4.10

在现有 §4.6（原型/Demo）之后新增 4 个跨项目共享场景：

#### 4.7 跨项目共享——同 WebApi 多前端

**场景**：多个前端项目（用户侧网站 + 商户后台）共用同一 WebApi，共享同一套 mock 数据。

**共享文件**：`MockDataSpec JSON`（规则）或 `DatasetSeed JSON`（数据）+ `MOCK_SPEC.md`（说明）。

**工作流**：
- 方案 1（规则共享）：各项目独立 `generateFromSpec(spec)`——同 seed 确定性 → 数据逐字节一致
- 方案 2（数据共享）：一方生成 `exportDatasetSeed` → 另一方 `importDatasetSeed` 加载
- 推荐：同 WebApi → 方案 1（规则便携，各项目可按需调 scenario）；跨 WebApi → 方案 2（数据自包含）

#### 4.8 跨项目共享——HttpServer 常驻数据源

**场景**：一个常驻 mock HTTP 服务，多客户端（TS 前端 / 非 TS / WebApi 后端）通过 GraphQL over HTTP 访问。

**部署**：

```typescript
import { MockHttpServer } from "@tkwf/tsclient-mock/server";
const server = new MockHttpServer({ transport, host: "0.0.0.0", port: 4000, cors: true });
await server.start();
// http://0.0.0.0:4000/graphql — 所有客户端可通过 HTTP 访问
```

**注意**：
- 单 Transport 实例共享状态：多客户端的 mutation 互相可见（非会话隔离）
- 适合联调/演示；不适合需要状态隔离的多租户测试
- CORS 默认启用，auth 默认关闭

#### 4.9 跨项目共享——CI 确定性数据

**场景**：多个仓库的 CI/测试需要同一份确定性数据。

**共享文件**：`DatasetSeed JSON`（提交到仓库或 CI artifact）。

**工作流**：

```typescript
// CI 环境
import { importDatasetSeed } from "@tkwf/tsclient-mock/server";
const db = createMockDb({ paymentLogs: [], storeInfos: [] });
importDatasetSeed(db, "test-fixtures/seed.json");
// db.query("paymentLogs") → 确定性数据，每次 CI 结果一致
```

#### 4.10 跨项目共享——跨语言（TS ↔ .NET）

**场景**：TS 前端和 C# 后端共享同一套 mock 数据规则。

**两条路径**（ADR09 已有设计）：
- **转换**：TS `exportDatasetSeed` → DatasetSeed JSON → C# `DacMigrator.JsonToDatabaseAsync()` 写入 PostgreSQL
- **重新生成**：C# Bogus 加载同一 `MockDataSpec JSON` 独立生成（同 seed 确定性）

### 2.4 MOCK_SPEC.md.template 新增 §6

#### 六、共享与移植指引

> 本文件在不同项目间共享时，注意各节的移植性差异。

| 节 | 可移植性 | 接收方操作 |
|----|---------|-----------|
| §1 API 映射表 | ❌ 项目特定 | 删除 `<!-- auto-generated -->` 标记段，用本项目 `ts-client.g.ts` 重跑 `gen-mock-handlers --mock-spec` |
| §2 数据策略 | ✅ 可移植 | 同 WebApi 可直接复用；不同 WebApi 需按本项目实体调整 |
| §3 表间关系 | ✅ 可移植 | 同 WebApi 可直接复用；不同 WebApi 需按本项目外键调整 |
| §4 schema 变更同步 | ✅ 可移植 | 命令通用，路径按本项目调整 |
| §5 MockDataSpec JSON | ✅ 可移植 | 语言无关的结构化规则，直接复用 |

**接收方导入步骤**：
1. 复制本文件到接收项目
2. 删除 §1 映射表 → 重跑 `gen-mock-handlers --mock-spec` 重新生成
3. 若同时接收 `MockDataSpec JSON` → 直接 `generateFromSpec` 生成数据
4. 若同时接收 `DatasetSeed JSON` → 直接 `parseDatasetSeed` + `buildDataset` 加载
5. `buildDataset(seed, { unknownTables: "warn" })` 检测表名不匹配（v1.4.2）
