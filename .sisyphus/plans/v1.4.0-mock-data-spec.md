## 一、背景与目标

### 1.1 现状

当前 `@tkwf/tsclient-mock` v1.3.1 的数据生成能力：

| 能力 | 现状 | 局限 |
|------|------|------|
| 字段生成策略 | `createMockFactory` 硬编码启发式（`EXACT_STRATEGIES`/`CUSTOM_STRATEGIES`/`SUFFIX_STRATEGIES`/`PREFIX_STRATEGIES`） | 无法外部配置，无法描述分布/权重/nullable |
| 数据交换格式 | `DatasetSeed`（`Record<string, Record<string, unknown>[]>`）已存在 | 无文件 I/O，无法导出/导入 JSON |
| faker 方法映射 | 硬编码在 `factory.ts` 内（`EXACT_STRATEGIES` 等 4 张表） | .NET 侧无法共享，无法外部维护 |
| skill 工作流 | Agent 逐字段手填 `data.ts` 的 `initialData` | 数据量随表膨胀，不可跨语言复用 |
| 规则模板 | 无（`MockFieldSchema` 是字段级描述符，无实体级/关系级/场景级概念） | 无法描述"50 条 PaymentLog，FK 引用 StoreInfo.Uid" |

### 1.2 目标

对齐 ADR09 §3.2（ts-client-mock 适配）的 5 个步骤 + §2.7（skill 设计）：

1. **扩展字段级规则能力**（ADR09 步骤 9）：新增 `MockFieldRule` 类型，含 `distribution`/`weights`/`nullable`/`validation`（不修改现有 `MockFieldSchema`，见 §2.2 决策）
2. **`loadMockDataSpec()` 加载器**（ADR09 步骤 10）：从 JSON 文件/字符串加载规则模板
3. **`generateFromSpec()` 规则驱动生成**（ADR09 步骤 11）：从 MockDataSpec 生成 DatasetSeed，复用 `createMockFactory` 但规则来自 spec
4. **`exportDatasetSeed()` / `importDatasetSeed()`**（ADR09 步骤 12）：DatasetSeed JSON 导入导出
5. **faker 方法映射表外置**（ADR09 步骤 13）：提取为 `faker-method-map.json`
6. **skill 演进**（ADR09 §2.7）：SKILL.md 更新为四步工作流 + 新增 JSON Schema 和示例文件

### 1.3 不做什么

- ❌ 不做跨语言 RNG 一致性测试（ADR09 验收标准 #9，属后续扩展 §3.3）
- ❌ 不做 `gaussian` 分布的 TS 原生实现（faker.js 无原生支持，首版标注为 `.NET only`，TS 侧遇 `gaussian` 降级为 `uniform`）
- ❌ 不做 `computed` 策略的自由表达式求值（首版仅支持结构化运算符格式，见 §2.1.4）
- ❌ 不做 .NET 侧的任何实现（属 `_TKWF` 仓库 V4.9.35 第一部分）
- ❌ 不修改 `createMockFactory` 现有启发式行为（向后兼容，spec 规则仅在 `generateFromSpec` 路径生效）
- ❌ 不改 `MockFieldSchema` 现有字段（新增可选字段，不删不改）

## 二、类型设计

### 2.1 MockDataSpec 类型族

`MockDataSpec` 是语言无关的规则模板，描述"生成什么数据、怎么生成"。新增独立类型族，不扁平扩展 `MockFieldSchema`——关注点分离。

#### 2.1.1 顶层类型

```typescript
/** 语言无关的 mock 数据规则模板 */
export interface MockDataSpec {
  /** JSON Schema URI（版本标识） */
  $schema?: string;
  /** 格式版本 */
  version: 1;
  /** faker locale（如 "zh_CN"） */
  locale?: string;
  /** 随机种子（确定性生成） */
  seed?: number;
  /** 实体规则 */
  entities: Record<string, MockEntitySpec>;
  /** 场景定义 */
  scenarios?: Record<string, MockScenarioDef>;
}
```

#### 2.1.2 实体级

```typescript
/** 单个实体的生成规则 */
export interface MockEntitySpec {
  /** 生成数量 */
  count: number;
  /** 是否要求所有字段都有规则（strict mode） */
  strict?: boolean;
  /** 字段规则 */
  fields: Record<string, MockFieldRule>;
  /** 关系定义 */
  relations?: MockRelationDef[];
}
```

#### 2.1.3 字段级规则

```typescript
/** 单个字段的生成规则——扩展 MockFieldSchema 的策略层 */
export interface MockFieldRule {
  /** 字段类型 */
  kind: "string" | "number" | "boolean" | "date" | "enum";
  /** 生成策略 */
  strategy: MockStrategy;
  /** 分布类型（strategy 为 range/enum 时生效） */
  distribution?: "uniform" | "weighted" | "gaussian" | "cyclic";
  /** 加权权重（distribution 为 weighted 时生效） */
  weights?: number[];
  /** nullable 概率配置 */
  nullable?: { weight: number };
  /** 有效性约束（校验阶段使用，不参与生成） */
  validation?: MockValidation;

  // —— strategy 相关字段（按 strategy 值取不同子集）——
  /** strategy: sequence */
  start?: number;
  /** strategy: ref */
  ref?: string;
  /** strategy: faker */
  fakerMethod?: string;
  /** strategy: range */
  min?: number;
  max?: number;
  /** strategy: dateRange */
  between?: [string, string];
  /** strategy: pattern */
  pattern?: string;
  /** strategy: constant */
  value?: unknown;
  /** strategy: sample */
  samples?: unknown[];
  /** strategy: enum（枚举值） */
  values?: (string | number)[];
  /** strategy: computed（结构化表达式） */
  compute?: MockComputeExpr;
}

/** 生成策略类型 */
export type MockStrategy =
  | "sequence" | "uuid" | "ref" | "faker" | "range"
  | "dateRange" | "pattern" | "computed" | "constant"
  | "sample" | "enum";
```

#### 2.1.4 computed 策略（结构化表达式）

**不使用自由表达式字符串**（安全考虑，禁用 `eval`）。采用结构化运算符格式：

```typescript
/** 结构化计算表达式——安全求值，无 eval */
export interface MockComputeExpr {
  /** 运算符 */
  op: "add" | "subtract" | "multiply" | "divide" | "coalesce";
  /** 操作数：字段引用或字面量 */
  operands: MockComputeOperand[];
}

/** 计算操作数 */
export interface MockComputeOperand {
  /** 引用实体内其他字段 */
  field?: string;
  /** 字面量值 */
  literal?: number | string;
  /** 嵌套表达式（支持 computed 嵌套，如 coalesce 作为 subtract 的操作数） */
  expr?: MockComputeExpr;
}
```

**示例**：`"TotalAmount - (DiscountAmount ?? 0)"` 表示为：
```json
{
  "op": "subtract",
  "operands": [
    { "field": "TotalAmount" },
    { "expr": { "op": "coalesce", "operands": [{ "field": "DiscountAmount" }, { "literal": 0 }] } }
  ]
}
```

支持嵌套（`expr` 字段引用嵌套表达式）。首版仅支持 5 种运算符，覆盖加减乘除和空值合并。

#### 2.1.5 关系定义

```typescript
/** 实体间关系——FK 引用 */
export interface MockRelationDef {
  /** 关系类型 */
  type: "belongsTo";
  /** 本实体外键字段 */
  field: string;
  /** 目标实体名 */
  targetEntity: string;
  /** 目标实体字段 */
  targetField: string;
  /** 生成时是否自动引用已生成的目标 ID */
  generate?: boolean;
}
```

#### 2.1.6 场景定义

```typescript
/** 场景——覆盖默认 count */
export interface MockScenarioDef {
  /** 实体名 → 覆盖的 count */
  [entityName: string]: { count: number };
}
```

#### 2.1.7 有效性约束

```typescript
/** 有效性约束（校验阶段使用，不参与生成） */
export interface MockValidation {
  /** 正则校验（string 字段） */
  regex?: string;
  /** 唯一性校验 */
  unique?: boolean;
  /** 非空校验 */
  notEmpty?: boolean;
  /** 业务最小值（与生成范围不同） */
  min?: number;
  /** 业务最大值 */
  max?: number;
}
```

### 2.2 MockFieldSchema 扩展（ADR09 步骤 9）

**不修改 `MockFieldSchema` 本身**。策略层信息（distribution/weights/nullable/validation）全部在 `MockFieldRule` 中。`MockFieldSchema` 保持字段级类型描述符角色不变。

理由：`MockFieldSchema` 被 codegen `parse-dto.ts` 从 TS 类型自动生成，职责是"描述字段类型结构"。`MockFieldRule` 是人工/skill 编写的生成策略，职责是"描述怎么生成值"。两者关注点不同，混在一起会导致 codegen 产物膨胀且需手写策略。

## 三、功能设计

### 3.1 扩展 MockFieldSchema → 不改，新增 MockFieldRule（步骤 9）

如 §2.2 所述，不修改 `MockFieldSchema`。新增 `MockFieldRule` 类型族（§2.1）全部在新建文件 `src/mock-data-spec.ts` 中定义。

### 3.2 loadMockDataSpec()（步骤 10）

**新增文件**：`src/mock-data-spec.ts`

```typescript
/** 从 JSON 字符串解析 MockDataSpec */
export function parseMockDataSpec(json: string): MockDataSpec;

/** 从文件加载 MockDataSpec（Node 环境，/server 子路径导出） */
export function loadMockDataSpec(path: string): MockDataSpec;
```

- `parseMockDataSpec(json)`：纯字符串解析，浏览器安全，主入口导出
- `loadMockDataSpec(path)`：文件 I/O，Node-only，`/server` 子路径导出

**校验**：加载时做结构校验（必填字段缺失、strategy 与字段不匹配等），不做业务约束校验（validation 字段仅记录不执行）。

### 3.3 generateFromSpec()（步骤 11）

**新增文件**：`src/mock-data-spec.ts`

```typescript
/** 从 MockDataSpec 生成 DatasetSeed */
export function generateFromSpec(
  spec: MockDataSpec,
  options?: {
    /** faker 实例（realistic 策略需要） */
    faker?: Faker;
    /** 现有 MockFieldSchema 映射（从 codegen 产物获取） */
    schemas?: Record<string, Record<string, MockFieldSchema>>;
  },
): DatasetSeed;
```

**生成流程**（对齐 ADR09 §2.3.3 BogusDataGenerator 逻辑）：

1. **拓扑排序**：按 `relations` 依赖排序实体，无 FK 依赖的实体先生成
2. **逐实体生成**：
   - 为每个字段构建生成器：
     - spec 有规则 → 用 `MockFieldRule` 构建生成函数
     - spec 无规则 → 回退到 `createMockFactory` 现有启发式（`resolveFieldStrategy`）
   - `ref` 策略 → 从已生成父实体的 ID 池中 PickRandom
   - `computed` 策略 → 标记为后处理，先生成占位值
   - `nullable` 概率 → 按权重决定是否为 null
   - `weighted` 分布 → `faker.helpers.weightedArrayElement`
   - `gaussian` 分布 → 降级为 `uniform`（首版，console.warn）
3. **后处理 computed 字段**：全部字段生成后，按 `MockComputeExpr` 求值
4. **返回 DatasetSeed**

**复用 `createMockFactory`**：`generateFromSpec` 内部对每个实体调用 `createMockFactory`，通过 `_generators` 参数注入 spec 驱动的生成函数。spec 未覆盖的字段回退到启发式。

**FK 关系**：生成父实体后收集 ID 池（`generatedIds` 字典），子实体 `ref` 策略从中取值。与 `MockDb.registerRelation` 运行时关系机制不耦合——`generateFromSpec` 只负责生成时 FK 设置，运行时关系仍由 `registerRelation` 管理。

### 3.4 exportDatasetSeed() / importDatasetSeed()（步骤 12）

**新增文件**：`src/dataset-io.ts`

```typescript
/** 序列化 DatasetSeed 为 JSON 字符串（浏览器安全，主入口导出） */
export function serializeDatasetSeed(db: MockDb): string;

/** 从 JSON 字符串加载 DatasetSeed 到 MockDb（浏览器安全，主入口导出） */
export function parseDatasetSeed(json: string): DatasetSeed;

/** 导出 DatasetSeed 到文件（Node-only，/server 子路径导出） */
export function exportDatasetSeed(db: MockDb, path: string): void;

/** 从文件导入 DatasetSeed 到 MockDb（Node-only，/server 子路径导出） */
export function importDatasetSeed(db: MockDb, path: string): void;
```

- `serializeDatasetSeed` / `parseDatasetSeed`：纯字符串操作，主入口导出
- `exportDatasetSeed` / `importDatasetSeed`：文件 I/O，`/server` 子路径导出，内部调用字符串版本 + `fs.readFileSync`/`writeFileSync`
- `importDatasetSeed` 内部调用 `db.buildDataset(parseDatasetSeed(json))`

### 3.5 faker-method-map.json（步骤 13）

**新增资源文件**：`src/mock-spec/faker-method-map.json`

从 `factory.ts` 的 4 张硬编码表提取为 JSON。`EXACT_STRATEGIES`/`SUFFIX_STRATEGIES`/`PREFIX_STRATEGIES` 是 `Record<string, string>`（字段名→faker 方法路径），可直接序列化。`CUSTOM_STRATEGIES` 是 `Record<string, (ctx) => unknown>`（函数），需转换为 `MockFieldRule` 格式：

```json
{
  "exact": {
    "name": "person.fullName",
    "userName": "person.fullName",
    "companyName": "company.name"
  },
  "custom": {
    "amount": { "kind": "number", "strategy": "range", "min": 1, "max": 99999 },
    "price": { "kind": "number", "strategy": "range", "min": 10, "max": 9999 },
    "discount": { "kind": "number", "strategy": "range", "min": 0, "max": 100 },
    "status": { "kind": "enum", "strategy": "enum", "distribution": "cyclic" },
    "createdAt": { "kind": "date", "strategy": "dateRange", "between": ["now-30d", "now"] },
    "deletedAt": { "kind": "date", "strategy": "constant", "value": null }
  },
  "suffix": {
    "Name": "person.fullName",
    "Phone": "phone.number"
  },
  "prefix": {
    "is": "boolean",
    "has": "boolean"
  },
  "regex": [
    { "pattern": "Time$|At$", "method": "__date__" },
    { "pattern": "Id$", "method": "__id__" }
  ]
}
```

> `custom` 节的 `status`/`state`/`level` 等字段原本依赖运行时 `ctx.enums`，JSON 格式中标记 `distribution: "cyclic"` + `strategy: "enum"`，实际枚举值在 `generateFromSpec` 运行时从 `MockFieldSchema.enumValues` 或 `spec.fields[field].values` 获取。

**加载方式**：`factory.ts` 使用 ESM import assertion（`import map from "./mock-spec/faker-method-map.json" assert { type: "json" }`）。Node 16+ 原生支持；浏览器端 bundler（Vite/webpack）配置 JSON import 后支持。`tsc` 编译时将 JSON 内联到产物，无需运行时 `readFileSync`，保持主入口浏览器安全。若 bundler 不支持 import assertion，降级为构建时 `fs.readFileSync` + 代码生成（`faker-method-map.g.ts`）。

**发布**：`package.json` 的 `files` 已含 `"src/mock-spec"`，JSON 文件自动随包发布。

**向后兼容**：`EXACT_STRATEGIES` 等常量保留为 `const`，从 JSON 初始化。外部代码无感知。

## 六、测试策略

### 6.1 单元测试

| 测试文件 | 覆盖 |
|----------|------|
| `src/mock-data-spec.test.ts` | parseMockDataSpec（合法/非法 JSON）+ generateFromSpec（各 strategy/distribution/nullable/computed/ref）+ 拓扑排序 + FK 引用 + gaussian 降级 |
| `src/dataset-io.test.ts` | serializeDatasetSeed / parseDatasetSeed 往返一致性 + exportDatasetSeed / importDatasetSeed 文件 I/O |

### 6.2 关键测试用例

1. `generateFromSpec` 生成 50 条 PaymentLog，字段值符合 strategy
2. `weighted` 分布统计 1000 条数据，权重比例误差 ≤ 5%
3. `nullable` 概率为 0.3 时，1000 条中 null 比例 25%-35%
4. `computed` 策略：`subtract(TotalAmount, coalesce(DiscountAmount, 0))` 正确求值
5. `ref` 策略：子实体 StoreUid 全部来自父实体 StoreInfo.Uid 池
6. spec 未覆盖字段回退到启发式（向后兼容）
7. `gaussian` 策略降级为 `uniform` + console.warn
8. `exportDatasetSeed` → `importDatasetSeed` 往返一致
9. `parseMockDataSpec` 缺必填字段时报错
10. faker-method-map.json 加载后 `resolveFieldStrategy` 行为不变

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| `generateFromSpec` 与 `createMockFactory` 启发式行为不一致 | spec 未覆盖字段回退到启发式，保证向后兼容 |
| `computed` 结构化表达式覆盖面不足 | 首版仅 5 种运算符，复杂计算留后续扩展 |
| faker-method-map.json 加载失败 | 降级到内联默认表 + console.warn |
| `ref` 策略在父实体未生成时报错 | 拓扑排序保证父实体先生成；循环依赖检测 |
| MockDataSpec 类型族与 MockFieldSchema 概念混淆 | 文档明确：MockFieldSchema = 类型描述符（codegen 生成），MockFieldRule = 生成策略（人工/skill 编写） |
| ESM `import json` 在非 Node 环境不支持 | 使用 `JSON.parse` + 构建时内联，或 `createMockFactory` 接受可选映射表参数 |

## 八、验收标准

对齐 ADR09 §5（TS 相关项）：

| # | 标准 | 验证方式 |
|---|------|----------|
| 1 | `parseMockDataSpec` 从 JSON 加载 MockDataSpec | 单测：合法/非法 JSON |
| 2 | `generateFromSpec` 从 spec 生成 DatasetSeed | 单测：字段值符合 strategy |
| 3 | `weighted` 分布生效（70% Paid） | 统计 1000 条分布，误差 ≤ 5% |
| 4 | `ref` 策略 FK 引用正确 | 单测：子实体 FK 全部来自父实体 ID 池 |
| 5 | `computed` 策略正确求值 | 单测：subtract/coalesce 嵌套表达式 |
| 6 | `exportDatasetSeed` / `importDatasetSeed` 往返一致 | 单测：序列化→反序列化等值 |
| 7 | spec 未覆盖字段回退到启发式 | 单测：只填部分字段，其余字段值与 `createMockFactory` 一致 |
| 8 | faker-method-map.json 加载后行为不变 | 单测：`resolveFieldStrategy` 返回值与硬编码一致 |
| 9 | `gaussian` 降级为 `uniform` + warn | 单测：warn 调用 + 值在 range 内 |
| 10 | SKILL.md 四步工作流完整 | 人工审查 |
| 11 | `npm run build` 编译通过 | CI |
| 12 | `npm test` 全部通过 | CI |
